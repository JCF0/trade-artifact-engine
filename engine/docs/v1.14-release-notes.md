# Artifact v1.14 Release Notes

## Wallet-Wide Bounded Acquisition v1

Artifact v1.14 adds the deterministic, read-only acquisition boundary that completes this path:

```text
wallet + permitted fixed lookback
→ finalized Solana anchor
→ canonical finalized wallet-signature history
→ exact Enhanced Transaction enrichment
→ exhaustive five-outcome transaction dispositions
→ wallet_wide_acquisition_result_v1
→ candidate_evidence_bundle_v1
→ wallet_candidate_set_v1
→ digest-only selection
→ exact existing Slice 7 dry-run request
→ unchanged receipt_package_v1
```

Finalized Solana `getSignaturesForAddress` history is the completeness index. Enhanced Transactions enrich the exact canonical signature set; Enhanced address history is not accepted as the completeness authority. Caps, truncation, timeout, uncertainty, stale-head detection, set mismatch, or protocol contradiction fail closed without an acquisition result.

v1.14 introduces no hosted storage, authentication, jobs/workers, API, UI, publication, package-store commit, upload, signing, minting, deployment, live marks, or trading-fund custody or control.

The first pre-hardening bounded provider-attested controlled live validation passed the then-current implementation. A distinct, later post-hardening controlled live validation also **PASS**ed for one approved public Solana mainnet-beta wallet using `lookback_7d_v1`. That later run examined two pages and reached the historical bound, observing 76 canonical signatures, five in-window transactions, and five Enhanced transactions reconciled. Its exact disposition partition was 1 supported, 0 unsupported, 1 ambiguous, 3 unrelated, and 0 failed. It produced one normalized event, one localized finding, one blocked summary, zero candidates and zero selectable candidates, with zero retries and zero timeouts. Acquisition, normalization, classification, pagination, historical-bound, and chain-boundary gates were proven. There was no cap, truncation, partial result, or provider uncertainty. No live candidate resolution or Slice 7 invocation occurred because there was no selectable candidate. Zero candidates was a valid result, not a validation failure. No package-store operation, publication, upload, signing, minting, or deployment occurred. The API key and raw provider bodies were absent from the sanitized report.

The later post-hardening classification totals matched the first pre-hardening run. Its sanitized report remains outside Git; its SHA-256 was `5f6b167ba07671e60ea3b9b09c5f65a5d8b98cf9e87bf810b5efa69bd42e1b76`, its size was 1,951 bytes, and its mode was `0600`. This remediation was implemented after that run. Deterministic remediation is complete, but one fresh post-remediation controlled live validation is still required before tagging. v1.14.0 is not yet tagged.

## Deterministic retained replay and integration proof

The complete direct-Node wallet-acquisition suite proves:

```text
exact retained Helius bodies
→ v1.14 Enhanced projection
→ wallet-wide acquisition
→ evidence bundle
→ candidate set
→ candidate resolver
→ Slice 7 dry-run request
→ targeted package dry run
```

The replay uses no package store. Targeted orchestration remains `dry_run`, and no package-store capability is supplied.

The tracked tree intentionally contains exactly five retained Helius fixture bodies for deterministic replay: `jup_buy`, `jup_sell`, `ray_buy`, `ray_sell`, and `jupiter_close_account_swap`. The retained RAY bodies carry the Helius source label `JUPITER`; provider source metadata is projected out and does not enter canonical candidate or package identity. Controlled-live raw responses are not retained. No exact retained finalized RPC transcript exists; synthetic finalized RPC pages are used in these tests. Orca, UNKNOWN, failed, mixed-disposition, ambiguity, and provider-error bodies are synthetic fixtures unless a test explicitly says otherwise. Synthetic provider-shaped tests are not retained live evidence.

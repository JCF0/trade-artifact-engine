# Artifact v1.14 Release Notes

## Wallet-Wide Bounded Acquisition v1

Artifact v1.14 adds the deterministic, read-only acquisition boundary that completes this path:

```text
wallet + permitted fixed lookback
→ finalized Solana anchor
→ canonical finalized wallet-signature history
→ exact Enhanced Transaction enrichment
→ exhaustive five-outcome transaction dispositions
→ wallet_wide_acquisition_result_v1
→ candidate_evidence_bundle_v1
→ wallet_candidate_set_v1
→ digest-only selection
→ exact existing Slice 7 dry-run request
→ unchanged receipt_package_v1
```

Finalized Solana `getSignaturesForAddress` history is the completeness index. Enhanced Transactions enrich the exact canonical signature set; Enhanced address history is not accepted as the completeness authority. Caps, truncation, timeout, uncertainty, stale-head detection, set mismatch, or protocol contradiction fail closed without an acquisition result.

v1.14 introduces no hosted storage, authentication, jobs/workers, API, UI, publication, package-store commit, upload, signing, minting, deployment, live marks, or trading-fund custody or control.

One bounded provider-attested controlled live validation was completed for one mainnet-beta wallet using `lookback_7d_v1`. It passed under the then-current implementation with two pages, 76 canonical signatures, five in-window transactions, and five Enhanced reconciliations: one supported, one ambiguous, and three unrelated. It produced zero candidates and zero selectable candidates; that was a valid result, not a failure, and no live candidate resolution or Slice 7 invocation occurred. There was no cap, timeout, truncation, partial state, provider uncertainty, package write, publication, signing, upload, mint, or deployment. This first live run predates the final exhaustive `accountData` reconciliation hardening. A fresh controlled validation is required after this patch before tagging; v1.14 has not been tagged.

## Deterministic retained replay and integration proof

The complete direct-Node wallet-acquisition suite proves:

```text
exact retained Helius bodies
→ v1.14 Enhanced projection
→ wallet-wide acquisition
→ evidence bundle
→ candidate set
→ candidate resolver
→ Slice 7 dry-run request
→ targeted package dry run
```

The replay uses no package store. Targeted orchestration remains `dry_run`, and no package-store capability is supplied.

Exact retained Helius bodies are `jup_buy`, `jup_sell`, `ray_buy`, `ray_sell`, and `jupiter_close_account_swap`. The retained RAY bodies carry the Helius source label `JUPITER`; provider source metadata is projected out and does not enter canonical candidate or package identity. Retained Solana RPC envelopes do not currently exist. Synthetic finalized RPC pages are used in these tests. Orca, UNKNOWN, failed, mixed-disposition, ambiguity, and provider-error bodies are synthetic fixtures unless a test explicitly says otherwise. Synthetic provider-shaped tests are not retained live evidence.

## Supervision and loss semantics

Outer fixed launcher derives one monotonic deadline from the minimum of `episode_timeout_ms` (1–600000) and remaining `runtime.deadline_unix_seconds`. It launches fixed namespace init with no application arguments. Parent-death SIGKILL is armed before exec with the parent-race check. Outer timeout kills the owned process group; unshare's kill-child chain terminates PID namespace init, whose death kills all namespace descendants, including changed process groups/sessions. Namespace init additionally uses subreaper traversal and bounded reaping. The outer deadline does not reset after child launch.

Synthetic evidence separately establishes helper parent-loss SIGKILL, pipe/FD closure, high descriptors above a lowered limit, same-UID subreaper double-fork/setsid cleanup, finite deadline, EOF, output loss and independent authenticated human revocation. It does **not** establish installed cross-UID custody or the complete production unshare/exec chain. Blocking uninterruptible kernel I/O cannot be represented as an instantaneous cleanup guarantee. Missing acknowledgement, supervisor loss, failure, state loss or deadline means STOP and preserve; never replacement signing, schedule refill, reprovisioning or automatic restart.

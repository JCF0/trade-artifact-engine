## Protocol basis: account meta is not initialized account data

No documentation fetch was necessary. The previously retained official Orca source
archives were hash-verified, and cited extracted source files were compared against
the actual archive members. Source evidence is retained in
`E/official-source-identity.json` and `E/calibration-correlation.json`.

Installed versions are client **7.0.0** and core **3.1.1**. Their retained upstream
commits are respectively `a119d79bada4e730fef791cac6adb669405a21de` and
`8c76d3bd55e3074d1cbb039f3e8e5de8f7bd0f7c`.

Relevant official source at the latter commit:

- `programs/whirlpool/src/instructions/swap.rs:44-52`: classic swap requires the
  seed-constrained oracle **UncheckedAccount**, normally read-only. The comment
  describing it as unused is not the complete behavior; the handler actually calls
  `OracleAccessor` at lines 78-82 and updates adaptive state at line 107.
- `programs/whirlpool/src/state/oracle.rs:405-435`: a system-owned, empty account is
  uninitialized; other representations receive owner/discriminator checks.
  At lines 364-402, an uninitialized oracle enables trading without oracle data,
  returns no adaptive-fee information, and skips mutation/writable access.
- `programs/whirlpool/src/instructions/initialize_pool.rs:8-49,63-74`: classic
  static-fee initialization does not create an oracle and uses fee-tier index equal
  to tick spacing.
- `programs/whirlpool/src/instructions/adaptive_fee/initialize_pool_with_adaptive_fee.rs:47-53,164-169`:
  adaptive-fee initialization creates and initializes the oracle, including trade
  enable timestamp and adaptive-fee parameters. When initialized, the accessor
  checks trade-enable time, loads adaptive fee state and updates its variables;
  this needs a writable oracle, either directly or through the remaining-account
  privilege described by classic swap. This is outside our read-only oracle profile.
- `programs/whirlpool/src/state/whirlpool.rs:309-310`: adaptive-fee classification
  is fee-tier index different from tick spacing. The pinned off-chain quote engine,
  `rust-sdk/core/src/quote/swap.rs:243-244`, rejects a mismatch between that
  classification and supplied adaptive-fee information.
- Installed client `dist/index.js:11545-11598`: classic instruction uses 11 account
  metas, derives the oracle from `oracle` plus the pool under the selected program,
  and marks it read-only. No account-data fetch is part of this pure construction.

**Protocol deduction:** this static-fee classic instruction needs the correct
oracle *address in its accounts*, not an initialized oracle body. The absent RPC
account is compatible with the uninitialized account path; creating an oracle is
neither required nor permitted here. Adaptive-fee handling would require additional
state validation and writable-account semantics and remains refused.

These are deductions from exact retained official source plus actual historical
execution evidence, not an independent attestation of today's deployed program
binary. No live program inspection or claim of future execution success is made.

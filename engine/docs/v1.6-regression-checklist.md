# v1.6 Regression Checklist

## Deterministic Automated Suites

Run:

```bash
node engine/src/run-v16-regression.mjs
node engine/src/check-v16-receipt-board-demo.mjs
node engine/src/run-v15-regression.mjs
node engine/src/run-v14-regression.mjs
```

Expected:
- all deterministic suites pass
- demo checker passes against the tracked receipt-board manifest and matching local inventory
- no live Helius, upload, mint, signing, browser automation, remote deploy, or network assumptions
- non-zero exit on failure

## v1.6 Suites Included

`run-v16-regression.mjs` includes all v1.5 deterministic suites plus:
- `engine/src/receipt-board/view-model.test.mjs`
- `engine/src/receipt-board/render-html.test.mjs`
- `engine/src/api/receipt-board-api.test.mjs`

The v1.2 ledger runner remains separate:
- `node engine/src/ledger/run-all-tests.mjs`

## Demo Checker Scope

Verify:
- `engine/samples/historical-receipt-board.manifest.json` contains at least one entry
- the first manifest `receipt_hash` exists in local canonical inventory before route checks begin
- `/api/receipt-board` returns `200 application/json`
- `/api/receipt-board/preview` returns `200 text/html`
- `/api/proof/:receiptHash` returns `200 application/json`
- `/api/verifier/:receiptHash` returns `200 application/json`
- `/api/proof/:receiptHash/card` returns `200 application/json`
- `/api/proof/:receiptHash/card/preview` returns `200 text/html`
- `/api/proof/:receiptHash/hosted-preview` returns `200 text/html`
- no unexpected fetch/network behavior occurs during checks
- no writes, browser automation, screenshots, export, publish, upload, mint, or signing side effects occur during checks

If the sample hash is not present locally, the checker fails with:

```text
historical receipt board sample hash not found in local inventory; run/generate sample inventory first
```

## Manual Smoke

1. Start the local API server with inventory matching `engine/samples/historical-receipt-board.manifest.json`.
2. Open `GET /api/receipt-board`.
3. Confirm JSON frames rows as receipt entries, not traders, wallets, profiles, portfolios, or skill.
4. Open `GET /api/receipt-board/preview`.
5. Confirm standalone local HTML renders receipt entries and required disclosures.
6. Follow links to proof detail, verifier JSON, card JSON, card preview, and hosted preview.
7. Confirm raw quote and selected-receipt disclosures remain visible.
8. Confirm no PnL ranking, USD normalization, lifecycle/upload/mint grids, transaction signatures, artifact URI grids, wallet totals, or participant totals are shown.

## Query Checks

Confirm:
- `wallet_display=full|truncated|redacted` is accepted
- `wallet_display=bad` returns 400
- `include_excluded=true|false` is accepted
- invalid `include_excluded` returns 400
- `limit` and `offset` accept non-negative integers only
- no unsupported metric query is exposed

Notes:
- board rows do not expose wallet fields, so `wallet_display` is currently validated and forward-compatible but effectively no-op for the board
- `count` currently reflects returned paged rows, not total ranked rows when pagination is used

## Exact incompatibility

Here A/ means `engine/src/verification-scope-v1-3/final-proof-agent/`.

1. **Readiness requires real setup-history corroboration.** `A/orca-readiness-capture-v1.mjs:230–261` paginates wallet and both token-account histories with a finalized context floor, retains all returned rows, requires exhaustion and an unchanged repeated head, and corroborates the frozen latest setup time. Setup history is expected, not an extraneous event invented by the exporter.
2. **The replay consumer treats all retained history rows as episode transactions.** `A/final-episode-release-v1.mjs:49–51` caps descriptor transactions at two. Lines 59–60 parse the complete retained signature pages; lines 83–85 require `pages.flat()` to equal exactly the reversed normalized transaction population, including count. This comparison happens before wallet-window acquisition at line 100. An older out-of-window row is therefore rejected rather than retained as completeness evidence and excluded from the economic population.
3. **The accepted fixture bypasses this operational shape through explicitly synthetic carriers.** `A/fixtures/retained-final-episode-v1.mjs:170–173` creates economic-history pages from only its generated episode transactions. Its readiness records separately contain setup history. This is valid historical synthetic acceptance, but not evidence that an exporter can preserve an original provider history page with a setup row through the same source contract.
4. **The descriptor cannot express an independently verified raw-page projection.** Its `history` object is closed to `genesis`, `slot`, `block`, `pages`. There is no original-request/boundary/projection mapping that lets independent replay establish why an older row was excluded. An auxiliary raw file with a checksum alone would not repair this semantic gap.

Using a narrower lookback alone does not repair the mismatch: the reproduced sentinel was strictly older than the configured lookback, yet the equality at line 85 rejected it before window selection. A future deliberately bounded `until` query would also need its exact request, predecessor boundary and exclusion proof retained and verified; silently introducing such a query is not an implementation of the current raw-page replay contract.

This finding does **not** assert that a live provider has returned a particular page, that every possible bounded query must return setup, or that the existing economic evaluator is defective. It establishes that the requested original-byte/completeness integration cannot support this valid source shape through the unchanged accepted consumer.

## Production controlled-live flow

The v1.15 operator accepts the closed CLI flag set, including explicit `--max-exact-fallback-transactions 0..8`, and constructs `wallet_wide_acquisition_request_v2`. It creates the fixed-origin Helius full-transaction port v2, binds one detached budget set and one acquisition-wide monotonic deadline, and runs `acquireWalletHistoryV2`.

The acquisition flow is:

1. validate Solana mainnet-beta identity;
2. derive a finalized anchor;
3. page finalized `getSignaturesForAddress` as the sole completeness authority and prove the lower bound;
4. perform the latest-state recheck;
5. page fixed-origin `getTransactionsForAddress` with `transactionDetails: "full"`, `commitment: "finalized"`, `encoding: "json"`, `maxSupportedTransactionVersion: 0`, `tokenAccounts: "none"`, `status: "any"`, `sortOrder: "desc"`, and page size: 100;
6. validate/detach/project full transactions and reconcile them to canonical signatures;
7. use finalized `getTransaction` only for an explicitly budgeted missing-signature-only fallback;
8. reuse unchanged v1 acquisition-result, evidence-bundle, candidate-set, digest-only selection, Slice 7 dry-run, receipt, and package boundaries.

Production has no dependency on the legacy Enhanced adapter/projector. Those modules are frozen offline oracle infrastructure only.

## Controlled-live report

Reports use `artifact_v1.15_controlled_live_validation_v1`. PASS reports include bounded canonical-source counts, all five disposition counts, canonical object digests, candidate counts, retry/timeout counts, and v2 telemetry:

- `full_transaction_pages_examined`;
- `full_transaction_entries_examined`;
- `full_transactions_reconciled`;
- `exact_fallback_transactions_requested`;
- `exact_fallback_transactions_reconciled`.

Malformed safe failures may include only `controlled_live_failure_diagnostic_v1` with fixed `stage`, `operation`, and `reason`. v1.15 stages add `full_transaction_history`, `full_transaction_projection`, and `exact_transaction_fallback`; operations add `full_transaction_address_history`, `full_transaction_validation`, `full_transaction_projection`, and `exact_transaction_fallback`; reasons are the fixed full-page/token/duplicate/order/shape/signature/projector/result classes plus `provider_value_unsafe` and the defensive fallback tuple.

Raw bodies, URLs, headers, API keys, pagination tokens, provider prose, stacks, local paths, and retry internals are excluded. Reports must use a unique nonexistent path under `/tmp`, outside the repository, exclusive `wx` creation, canonical JSON, fsync, and mode `0600`.

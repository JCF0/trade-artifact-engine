# Artifact v1.10 Public Read-Only Demo

Artifact v1.10 builds a deterministic local static bundle for an unlisted public demo and adds deployment-readiness checks for a manual Cloudflare Pages Direct Upload review.

## Build Commands

Dry run:

```bash
node engine/src/public-demo/cli.mjs --dry-run
```

Write:

```bash
node engine/src/public-demo/cli.mjs --write --out engine/data/public-demo --visibility unlisted --wallet-display truncated
```

Use `--force` only to replace a known generated output directory:

```bash
node engine/src/public-demo/cli.mjs --write --out engine/data/public-demo --visibility unlisted --wallet-display truncated --force
```

Predeploy check:

```bash
node engine/src/public-demo/predeploy-check.mjs --root engine/data/public-demo
```

## Output

The bundle contains exactly:

- `404.html`
- `_headers`
- `board.json`
- `index.html`
- `manifest.json`
- `robots.txt`
- `receipts/<slug>/index.html`
- `receipts/<slug>/proof.json`
- `receipts/<slug>/manifest.json`
- `verifier/<receipt_hash>.json`

There is one static receipt directory per selected manifest hash. Only the two publisher-selected JUP and RAY receipt hashes from `engine/samples/historical-receipt-board.manifest.json` are eligible.

## Safety Boundaries

The builder fails closed unless every selected receipt is:

- `closed_position`
- `verification_status=verified`
- hash-valid, schema-valid, consistency-valid
- verifier-passed
- `valuation_status=raw_quote`

The output is static and read-only. It does not run a server, database, account system, wallet connect flow, upload, mint, signing flow, Helius call, Cloudflare API call, or live network product call.

The generated public files preserve receipt-scoped Coverage Statements and raw quote disclosures. They do not claim portfolio coverage, full history, trader skill, track record, prize eligibility, anti-wash validation, leaderboard rank, or USD-normalized PnL.

Wallet display is truncated by default. Truncated public keys can still be correlatable on-chain.

## Static Hosting Files

`_headers` uses a global `/*` rule with strict security headers:

```text
Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; img-src 'self'; connect-src 'none'; script-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: geolocation=(), camera=(), microphone=(), payment=(), usb=()
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-origin
X-Robots-Tag: noindex, nofollow
```

No custom `Cache-Control` rules are included in this first deployment-readiness slice. Use hosting defaults until the deployed review is complete.

`robots.txt` contains:

```text
User-agent: *
Disallow: /
```

This reduces discovery only. It is not privacy, access control, authentication, or secrecy. Anyone with the URL can view the demo.

`404.html` is static, minimal, and links back to `/index.html`. It adds no product claims.

## CSP Compatibility

The predeploy checker proves the generated bundle requires no CSP weakening by checking:

- no `<script>` tags;
- no inline event handlers;
- no `javascript:` URLs;
- no browser network primitives such as `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `sendBeacon`, or dynamic `import`;
- no external image sources;
- no `data:` image or CSS asset URLs.

If a future output genuinely requires data URLs or another source, stop and review the design instead of weakening CSP automatically.

## Manual Cloudflare Pages Direct Upload

Use a dedicated Cloudflare Pages Direct Upload project for the first public review.

1. Generate and check the bundle:

```bash
node engine/src/public-demo/cli.mjs --write --out engine/data/public-demo --visibility unlisted --wallet-display truncated --force
node engine/src/public-demo/predeploy-check.mjs --root engine/data/public-demo
```

2. In Cloudflare Pages, create a Direct Upload project.
3. Upload only the contents of `engine/data/public-demo`.
4. Use the default `pages.dev` URL only.
5. Do not connect GitHub.
6. Do not add a custom domain.
7. Do not configure Functions.
8. Do not add environment variables.
9. Do not change DNS.

A Direct Upload project is a dedicated preview project and cannot later be converted to Git integration. Create a separate Git-backed project later if needed.

## Deployed-Site Review

On the default `pages.dev` URL:

- `/index.html` loads.
- Board shows only selected JUP and RAY entries.
- Receipt links open both static proof pages.
- Both `proof.json` files load.
- Both verifier JSON files load.
- Invalid paths show `404.html`.
- `robots.txt` returns `User-agent: *` and `Disallow: /`.
- Response headers include the configured CSP and `X-Robots-Tag: noindex, nofollow`.
- Browser developer tools show no scripts and no network calls beyond static file loads.
- Wallets remain truncated.
- Coverage Statements and raw quote/no-USD disclosures remain visible.
- No `/api/`, localhost, local path, raw/debug/archive bundle, full wallet, account, signing, upload, mint, database, mainnet, portfolio, full-history, track-record, trader-skill, anti-wash, prize, leaderboard-rank, or USD-PnL claim appears.

## Rollback

Use the Cloudflare Pages deployment list to restore the previous Direct Upload deployment. Do not change DNS or add a custom domain during v1.10 review.

## Determinism

The build does not call Git and does not use a current timestamp. `--source-revision` is optional caller-supplied metadata. Repeated builds from identical inputs produce byte-identical files.

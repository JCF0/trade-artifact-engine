# Wiggles supervised signing/retention candidate: deployment contract

## Status and existing conventions

This is an offline-qualified candidate, NOT permission to execute a live episode. `run-wiggles-supervised-v1.mjs` calls the unchanged blocked `createArtifactFinalProofLiveExecutorV1({})` before reading arguments, environment configuration, input channels, authority or wallet files. It exits 1 with `bounded_agent_live_executor_not_released`. There is no enable flag. The concrete executable composition is exported only as `createOfflineTrustedWigglesRuntimeV1`; it accepts exclusively the separately domain-labeled, fixed disposable wallet mandate. The production structural validator is read-only and cannot unlock that factory.

Repository inspection found Node one-shot CLI conventions and the existing Solana JSON array of 64 secret-key bytes with Ed25519 dependencies; no tracked systemd/PM2/container deployment convention exists for this executor. Reuse Node and supervised inherited pipes, not a web service, general daemon, scheduler, or remote rollback service. `engine/deployment/wiggles-supervised-v1.example.mjs` records the concrete proposed command/environment/paths and intentionally incomplete configuration. It is NOT an installer; neither this file nor the CLI provisions or starts anything automatically. The CLI currently does not consume the template at all.

## Candidate application path

Trusted administrator configuration supplies immutable mandate/authorization, expected public wallet, release identity, existing SQLite state root, key-file location, budget table and capture deadline. The offline construction additionally receives a trusted synthetic transport/clock; no transport is constructed from agent data. A future production source release must fix a conforming read-only provider transport and trusted wall/monotonic clocks in this same executor process. No synthetic transport is an approved provider.

1. Validate closed configuration, complete mandate, human authorization signature/static principal bindings, expected wallet, release and budget-table canonical SHA-256. Open the existing authority; never provision, reconstruct, restore or reenroll on runtime open.
2. Supervisor (not Hermes) requests readiness for the selected leg. Existing executor-owned capture establishes opening/history/route/quote/blockhash/fee evidence and cached freshness. Its evidence sink now writes canonical content-addressed evidence into the private state root using exclusive creation, file/directory fsync and bounded no-follow readback. Register the issued challenge in the existing SQLite authority. Challenge output can be provided to Hermes, but not source ports or build inputs.
3. Hermes writes exactly one existing canonical authenticated decision envelope to its supervised input pipe and closes the write end. `serveSingleWigglesDecisionV1` bounds this to 131072 bytes and an explicit wait of at most 60000 ms; proposed wait is 30000 ms. A complete envelope is one canonical JSON record, not JSONL, a command selector, or a shell command. Receipt of EOF does not imply authorization.
4. The fixed agent interface derives time from the trusted clock and calls existing authenticated ingress. It authenticates before durable lookups; the challenge/state, not Hermes, determine admission and quantity. Existing SQLite authority serializes consumption/revocation and advances RESERVED → PREPARED → KEY_LOAD_STARTED_AMBIGUOUS.
5. Exact Orca composition verifies the matching private plan, durable checkpoint and freshness before invoking its private key adapter. Only now is the configured key opened. Read at most 4096 bytes through a verified descriptor; require a private, executor-owned, single-link regular file under a private parent with no symbolic-link traversal. Validate exactly 64 integer bytes, derive and compare the public half and configured expected public wallet. After file IO/key derivation, recheck revocation/checkpoint and cached freshness again before Ed25519 signing. Wipe retained byte/number/secret arrays on success or failure. JavaScript strings, VM copies and crypto internals cannot be guaranteed erased; this is not HSM-grade memory confinement.
6. Verify signature and exact message; retain the exact wire with file/directory fsync through the existing Orca adapter. Existing SQLite registration independently reopens, fully parses and verifies retained wire before committing SIGNED_INTENT_DURABLE. Complete the existing episode-state transition before returning success.
7. Hermes receives only `{status, episode_id, signed_intent_digest}`. A refusal has status REFUSED and null intent. Failed pipe/ingress/signing/retention outcomes yield NOT_SUCCESSFUL with SUPERVISOR_RECONCILIATION_ONLY_NO_REPLACEMENT; this intentionally does NOT assert that nothing was consumed or signed. Original typed exceptions and durable checkpoint records remain available inside trusted execution. A lost output is not permission to retry signing. The executor-only `trusted.readRetainedWireV1(ordinal)` reuses the SQLite authority's complete wire verifier on every call, and is not exposed over the channel. Readback is NOT permission to submit.

No closure/submission/finalization method is exposed by this runtime. The existing chain-derived disposal check remains in the reused Orca composition/capture. A future disposal requires previously closed acquisition evidence in durable authority; this slice does not manufacture it.

## Proposed filesystem and process separation — NOT verified on this host

Names/paths are deployment proposals, not accounts or directories created here:

| Surface | Required owner/access |
|---|---|
| `/opt/artifact/release` and all parents, dependencies, Node binary, launcher | root/trusted administrator; runtime/controller read/execute only, no writes or mutable module search path |
| Administrator public configuration and release approval under `/etc/artifact-wiggles` | root-owned directory 0750, configuration 0640 with an explicitly runtime-readable group; Hermes no write access; no secrets in launch env/argv |
| `/var/lib/artifact-wiggles` parent | administrator-owned, no Hermes write or traversal into private descendants |
| `.../key` | artifact-wiggles UID, mode 0700; key file same UID, 0400 (0600 also passes application checks), regular, single link, no symlinks; administrator provisions out of band |
| `.../episode` | artifact-wiggles UID, 0700; provisioned database, WAL/SHM, wire and evidence private 0600; runtime can mutate but Hermes cannot read/write/traverse |
| Hermes control key/store | artifact-hermes UID only; Wiggles receives only configured agent public identity and signed envelope |
| Human authorization/revocation signing | human-controlled key, NOT Hermes or Wiggles; only authenticated public records supplied to the executor |

Trusted administrator provisions the initial episode once through the existing explicit provisioning API, outside the runtime command. Runtime source never calls provisioning. Restrict administrative shell/sudo/service-management rights: Hermes must not launch arbitrary code as Wiggles/root or supply a different module, loader, argv, NODE_OPTIONS, environment, cwd, filesystem root, FD table or signer. Launch with an explicit clean environment, umask 0077, no inherited unrelated descriptors, no debugger/inspector, no core dumps, and no automatic restart. No live endpoint is currently configured. A future network policy must permit only the approved read-only provider capability until submission is separately reviewed/authorized.

A trusted supervisor starts the fixed process under the runtime UID, retains the supervisor/revocation side and relays only readiness plus the decision-result projection to Hermes. Hermes gets solely the decision pipe write end and result pipe read end. Human revocation uses the trusted supervisor-side authenticated API, never an agent-selected operation on its pipe. The offline tests exercise the same one-envelope pipe handler in memory, not cross-UID descriptor provisioning. No cross-UID broker is installed or asserted operational here. Exact account/group assignment and the supervisor's descriptor handoff remain deployment decisions.

Before a later live release, verify under actual UIDs that Hermes cannot read keys/state/wire, replace code/config/key ancestors, ptrace or inspect runtime memory/`/proc/.../fd`, inherit privileged descriptors, or invoke provisioning/sudo as Wiggles. Verify runtime cannot modify release/provisioning files, Node modules are pinned/read-only, the filesystem supports the tested fsync/SQLite guarantees, and human revocation remains available during signing ambiguity. Private APIs and unit tests are not proof of these properties. Same-UID malicious runtime code and privileged administrator compromise are outside this supervised trust scope.

## Configuration and approval gates

All five live values must be explicitly supplied through the existing `mandate.unresolved_live_readiness` contract: human authorization public key, agent-control public key, acquisition not-after Unix second, RPC budget-table SHA-256, final executor release SHA-256. The field name is historical; status must reconcile to RESOLVED. The signed human authorization must bind this exact immutable mandate, release and interval. The expected public wallet is the unchanged final-proof wallet. Freeze actual setup evidence hashes, finite capture deadline and the exact bounded method budget object, whose canonical SHA-256 must match the mandate.

Production preflight rejects the separate test profile, fixed published controller keys, keys equal to offline fixtures, repeated-character placeholder keys/hashes, absent/mismatched values, invalid signatures, and expired acquisition authority. These checks establish structural consistency and authentication to configured public keys, NOT that an arbitrary non-placeholder key belongs to the real human/agent, that a setup digest has approved provenance, or that a candidate source hash is an approved release. Trusted administrators/humans must verify those facts independently. No generated test identity or source-manifest hash in this slice is a release approval. A later reviewed source release is required to connect production configuration/transport to the mechanically disabled live entry point; operators cannot toggle it.

## Restart, retention and remaining gates

Normal restart reopens existing authority with no cached readiness adoption or replacement plan. Exact concurrent/replayed decisions cannot obtain replacement signing. If authority is absent/corrupt, or an administrator knows it was restored/reprovisioned, stop and preserve evidence. Automatic detection of an internally valid administrator-restored older snapshot is expressly excluded; no external rollback authority is introduced.

Existing crash/replay tests prove the reused SQLite checkpoints and coupled transitions, including real process-kill tests; new runtime tests prove composed signing/retention failures and ordinary reopen with disposable keys. They do not claim a new cross-UID deployment or real-wallet crash campaign. Future live-only submission and reconstruction gates remain: reviewed exact-byte SUBMISSION_POSSIBLE integration; maximum 3 total identical-byte sends, at most 2 rebroadcasts, provider retries 0; no requote/rebuild/blockhash refresh/re-sign/replacement/cleanup; no Helius Sender, tips, priority fees or Compute Budget; finalized status/expiry/absence resolution; exact raw evidence retention; child-artifact verification; source-authoritative v1.3 reconstruction, Orca projection, production bridge and explicit immutable candidate selection. There is no automatic evidence promotion and no transmission integration in this slice.

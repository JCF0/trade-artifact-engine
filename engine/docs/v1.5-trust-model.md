# Artifact v1.5 Trust Model

## Scope

v1.5 Slice 1 adds a shared trust and disclosure layer for proof surfaces.

It is intended for:
- proof detail
- verifier surfaces
- receipt cards
- gallery/sample surfaces
- hosted/static proof pages

It does not modify:
- canonical v1.2 receipt schema
- receipt hash derivation
- accounting logic
- ledger verifier logic
- upload, mint, signing, or network behavior

## Design Goal

Trust messaging must be derived from facts already present on the local proof or inventory record.
Display and distribution choices must not be mislabeled as proof-strength upgrades.

Trust levels are monotonic. A receipt cannot receive Level N unless all requirements for lower levels are satisfied.

## Trust Levels

### Level 1 - Generated Receipt

The selected receipt exists as a generated artifact with receipt identity fields.

Current derivation:
- `receipt_hash` present
- `receipt_id` present

### Level 2 - Hash Verified

The receipt hash matches recomputed verification output.

Current derivation:
- Level 1 satisfied
- `hash_valid === true`

### Level 3 - Rule Verified

The receipt passed the existing verifier checks.

Current derivation:
- Level 2 satisfied
- `verifier_passed === true`
- `verifier_schema_valid === true`
- `verifier_consistency_valid === true`

This is a read-only interpretation of existing verifier outputs.
It does not add new verification logic.

### Level 4 - Source Anchored

The proof exposes one or more source anchors that allow outside correlation.

Current derivation:
- Level 3 satisfied
- at least one exposed source anchor

Current recognized anchors:
- `transaction_signature`
- `mint_address`
- `token_account`
- `metadata_uri`
- `image_uri`
- `final_metadata_uri`
- `final_image_uri`
- `external_url`

Level 4 is not a privacy claim.
If anchors are exposed, the surface is correlatable.

### Level 5 - Coverage Scoped

The surface includes an explicit coverage statement describing what scope the proof does and does not cover.

Current derivation:
- Level 4 satisfied
- explicit `coverage_statement` or `coverage_scope` present on the input record

v1.5 Slice 1 does not invent this statement automatically.
If no explicit statement exists, Level 5 remains planned or unavailable.

## Required Shared Disclosures

All shared proof surfaces should be able to render:
- `Selected receipt only. Not a portfolio statement.`
- `Raw quote only. No USD normalization.`
- `Wallet display may be truncated or redacted by publisher.`
- `Hosted, unlisted, and private labels describe display or distribution choices only. They do not increase proof strength.`

When source anchors are exposed, surfaces should also render:
- `Source anchors make this proof correlatable and should not be treated as private.`

## Release Boundaries

Slice 1 adds helper modules and additive proof-detail fields only.

It does not add:
- verifier pages or routes
- gallery pages
- new UI flows
- remote hosting
- accounts, profiles, or leaderboards
- price fetching or USD normalization

## Compatibility Notes

- Existing v1.3 and v1.4 proof-detail sections remain intact.
- New trust and disclosure fields are additive.
- `raw_quote` remains the valuation boundary and is not reinterpreted.

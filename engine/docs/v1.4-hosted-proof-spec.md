# v1.4 Hosted Proof Spec

## Slice 1 Scope

Slice 1 prepares proof detail rendering for future hosted and unlisted proof pages without adding hosting, publishing, uploads, accounts, remote deploys, minting, signing, price fetching, USD normalization, Helius balance-at integration, or mainnet work.

Files in scope:
- `engine/src/proof-publish/wallet-policy.mjs`
- `engine/src/proof-export/render-static-page.mjs`

## Wallet Display Policy

Wallet display policy is a render-only transform applied to a proof detail view-model.

Rules:
- supported modes are `truncated`, `redacted`, and `full`
- the transform must not mutate the input proof detail object
- the transform must not modify canonical receipts, inventory records, `receipt_hash`, verifier outputs, or source artifacts
- `truncated` shortens the wallet for display
- `redacted` replaces the wallet display value entirely
- `full` preserves the wallet display value unchanged

## Hosted Render Context

Hosted context is optional and additive.

When hosted context is enabled:
- wallet display mode defaults to `truncated`
- hosted disclosures must be rendered explicitly:
  - `Hosted proof page.`
  - `Unlisted does not mean private. Anyone with the link can view.`
  - `Selected receipt only. Not a portfolio statement.`
  - `Raw quote only. No USD normalization.`
  - `Wallet may be truncated or redacted by publisher.`
- `verification_status`, `hash_valid`, `verifier_passed`, and `proof_lifecycle` remain visually and logically separate

When hosted context is omitted:
- local v1.3 export behavior remains unchanged

## Non-Goals

This slice does not add:
- CLI publish flows
- publish bundle building
- API routes for hosted pages
- remote storage or uploads
- login, accounts, or wallet linking
- UI changes

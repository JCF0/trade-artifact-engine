# v1.4 Hosted Proof Spec

## Scope

v1.4 prepares local hosted-style proof surfaces without adding remote deployment, uploads, accounts, minting, signing, price fetching, USD normalization, Helius balance-at integration, or mainnet work.

Files in scope:
- `engine/src/proof-publish/wallet-policy.mjs`
- `engine/src/proof-publish/slug.mjs`
- `engine/src/proof-publish/publish-bundle.mjs`
- `engine/src/proof-publish/fs-adapter.mjs`
- `engine/src/proof-publish/cli.mjs`
- `engine/src/proof-export/render-static-page.mjs`
- `engine/src/api/server.mjs`

## Wallet Display Policy

Wallet display policy is a render-only transform applied to a proof detail view-model.

Rules:
- supported modes are `truncated`, `redacted`, and `full`
- the transform must not mutate the input proof detail object
- the transform must not modify canonical receipts, inventory records, `receipt_hash`, verifier outputs, or source artifacts
- `truncated` shortens the wallet for display
- `redacted` replaces the wallet display value entirely
- `full` preserves the wallet display value unchanged

## Hosted Render Context

Hosted context is optional and additive.

When hosted context is enabled:
- visibility defaults to `unlisted`
- wallet display mode defaults to `truncated`
- hosted disclosures must match the selected visibility:
  - `unlisted`: `Hosted proof page.` and `Unlisted does not mean private. Anyone with the link can view.`
  - `public`: `Public hosted proof page.`
  - `private`: `Private draft proof page.` and `Private here means local draft semantics only. Do not assume server-side privacy.`
- all hosted modes must preserve:
  - `Selected receipt only. Not a portfolio statement.`
  - `Raw quote only. No USD normalization.`
  - `Wallet may be truncated or redacted by publisher.`
- `verification_status`, `hash_valid`, `verifier_passed`, and `proof_lifecycle` remain visually and logically separate

When hosted context is omitted:
- local v1.3 export behavior remains unchanged

## Publish Bundles

v1.4 publish bundles are local scaffolds only.

They include:
- `index.html`
- `proof.json`
- `manifest.json`

Bundle generation can be previewed in memory and written locally through the publish CLI, but v1.4 does not deploy bundles remotely.

## Hosted Preview API

Slice 4 adds a local hosted-preview API route:
- `GET /api/proof/:receiptHash/hosted-preview`

This route is:
- read-only
- preview-only
- non-writing
- non-deploying
- local only

It does not create bundle files or provide a hosted service.

## Non-Goals

v1.4 does not add:
- remote deployment
- remote storage or uploads
- minting or signing flows
- login, accounts, or wallet linking
- UI changes
- mainnet publish workflows

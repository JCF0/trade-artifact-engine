## Implemented execution and failure path

The concrete runtime freezes trusted configuration, verifies mandate/human authorization, exact release, public wallet and canonical budget-table identity, then opens pre-existing SQLite authority. No key is opened during construction. A trusted supervisor invokes readiness capture and durable challenge registration. Hermes receives no signer, executable callback, file location, authoritative state, quote, quantity or message/wire capability: its sole input is the existing canonical authenticated decision envelope as bytes, terminated by EOF. Runtime time is executor-owned, not a channel parameter.

The reused authenticated ingress verifies the decision signature and trusted static principal bindings before authority lookup. It loads current state and the executor-issued challenge, consumes the decision/ordinal durably, prepares the exact challenge-bound Orca message and records PREPARED then KEY_LOAD_STARTED_AMBIGUOUS. Private composition checks that checkpoint and cached freshness before any key loading.

The actual adapter reads only the configured private bounded JSON file, validates its 64-byte key format and derived public half, and compares the public wallet identity. After key-file IO/derivation it rechecks durable revocation/checkpoint and cached freshness before signing once. It clears retained mutable secret arrays on both success and failure; VM/string/crypto-internal erasure is not claimed. Exact message/signature verification and exclusive fsync-backed wire retention precede the existing authority's independent read/parse/cryptographic verification and SIGNED_INTENT_DURABLE registration. The existing signed episode-state transition completes before success is returned.

Hermes sees only status, episode ID and signed-intent digest. Authenticated refusal returns REFUSED with null intent. A channel failure returns NOT_SUCCESSFUL with SUPERVISOR_RECONCILIATION_ONLY_NO_REPLACEMENT; it never asserts the decision is unconsumed or definitely unsigned. Typed failures and durable states remain available within trusted supervision. Wire can be reread only through the executor-side ordinal-selected method, which revalidates exact retained bytes on each access. That read is not a submission permission.

At any failed/ambiguous checkpoint, ordinary reopen preserves consumption. No replacement signing, challenge adoption from a restarted capture, automatic reenrollment or state recreation is performed. Lost output does not justify retrying signing. The new readback method changes no authority state. Capture evidence persistence before admission can leave unreferenced evidence after a failure, but cannot grant readiness or reset consumed authority.

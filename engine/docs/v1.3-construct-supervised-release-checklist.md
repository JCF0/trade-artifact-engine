# Construct supervised bounded-agent release checklist

## Approved release contract: option 1

The user has approved one human-authorized, supervised bounded-agent episode under trusted deployment administration. Hermes directs the two bounded decisions; Wiggles independently enforces the immutable mandate and owns signing authority. Executor-owned durable state survives ordinary process crashes/restarts. Controller provenance is not economic authority.

**Automatic detection of administrator restoration of an older internally valid snapshot is NOT a guarantee of this release.** External generation/head infrastructure is deferred. This is an explicit scope change, not implementation of rollback protection. Preserve the external-authority design in `v1.3-bounded-agent-rollback-deployment-decision.md` for any future stronger release.

A known restore, reprovisioning, loss of authoritative state, or ambiguous recovery requires stopping the episode. No automatic reenrollment, execution reset, requote, blockhash refresh, replacement signing, or replacement transaction is permitted. Ordinary restart reopens existing authority; missing authority must never trigger provisioning. An operator must preserve the database, retained wire, and evidence and seek separate authorization for any reconciliation. The system cannot automatically detect every restore. This operator policy relies on trusted administrators and supervision, not a hidden freshness detector.

The live entry point remains mechanically disabled. Option 1 does not approve live execution, wallets, credentials, deployment changes, scheduler activation, or an execution window.

## Implemented offline adapter slice

- `orca-message-boundary-v1.mjs` validates the frozen mandate and constructs a one-signer legacy message containing exactly one direct classic Whirlpool swap. It fixes the wallet, token accounts, pool, vaults, oracle, token program, account privileges, direction, exact input, minimum output, and direction-specific sqrt-price limit. It derives tick-array PDAs using the calibrated acquisition/disposal rules. No Compute Budget, ATA, cleanup, memo, additional instruction, ALT, or alternate route can enter the generated message.
- The prepared semantic digest covers the complete private message plan, including the serialized message hash. Byte equality, not merely independently supplied hashes, binds signer output to that message. All bytes are covered by alteration tests.
- `orca-signing-composition-v1.mjs` exposes only the existing authenticated Wiggles control-plane API. Its execution and signing ports are private closures. It uses executor-owned durable state for disposal quantity/evidence, checks the challenge-bound build input and exact-message fee binding, and requires the matching `KEY_LOAD_STARTED_AMBIGUOUS` row before invoking the injected signer once. A process-local consumed plan supplements, but never substitutes for, durable consumption.
- `orca-signed-wire-boundary-v1.mjs` verifies the exact message and Ed25519 signature, exclusively creates the ordinal-specific file, fsyncs file and directory, and reopens with no-follow and metadata/readback checks. The enclosing existing control plane commits `SIGNED_INTENT_DURABLE` after its independent retained-wire verification before returning an intent. No wire is released by the new API, and no transport is added.
- Known signing uncertainty cannot regenerate a plan after reopen through this composition. This guarantee assumes no administrator rollback of authoritative state, as explicitly approved above.

### Evidence limitations and explicit blocking inputs

The message builder is pure, not a live readiness authority. The implemented executor-owned readiness capture supplies bounded opening/history/route/quote/blockhash/fee validation and private freshness, and the composition binds those inputs to an issued challenge and the fee to the exact message. The four capture findings and rentEpoch compatibility repair are closed. This is offline qualification: provider completeness/context-floor conformance, real budgets and production transport remain deployment gates. A hash is not proof of source truth or freshness; no live defaults are invented.

The pure builder's retained-quantity argument is not independently authoritative on its own; only the composed path loads that value from the durable episode and checks the acquisition-evidence binding. Similarly, the generic signed-wire utility establishes cryptographic/retention identity, not admission or economic authority.

The trusted-runtime slice now exercises capture through durable signed-intent registration with the actual JSON-key adapter under a separately domain-labeled disposable-wallet test mandate. The frozen final-proof validator is unchanged and rejects that profile; production configuration rejects it as well. Shared control/capture/message call sites dispatch this distinct offline profile without relaxing final-proof scope or economic validation. Final-proof-shaped tests still use inert signers. No real-wallet key is loaded and no complete end-to-end live signer acceptance is claimed. See `v1.3-wiggles-trusted-runtime-deployment.md` for the application path, configuration contract, one-envelope channel, and unverified host assumptions.

## 2. Blocker B1 — incomplete inherited-FD closure in the verifier

**Severity:** blocking confinement/authority-boundary defect in the candidate's independent-verifier implementation.

**Exact source locations:**

- `P/verify-isolated.py:49–51`: core limit is set, then `os.closerange(3, 65536)` runs before confinement.
- `P/verify-isolated.py:63–67`: the launcher reports `authority='NO_READ_OR_WRITE_GRANT'` and execs the pinned Node process.
- `P/verifier-sandbox.py:25–42`: Landlock grants new path access only to the enumerated files/directories.
- `P/verifier-sandbox.py:45–56`: the seccomp policy assumes no inherited network descriptors and permits unlisted ordinary descriptor I/O syscalls.
- `P/OPERATOR.md:63`: the published guarantee says the launcher “closes FDs >=3” and confines reads to inventoried/package files.

**Reachable scenario — static deduction, not executed:**

1. A custodian launches the documented verifier with a genuine R, unchanged release files and a valid package. The parent inadvertently has an **inheritable** open descriptor numbered 65536 or higher, for example a read-only synthetic authority canary, a writable file, or an already-connected socket. No malicious replacement of release code or administrator rollback is needed for this descriptor leak.
2. `closerange` excludes its upper endpoint: it closes 3 through 65535, leaving that descriptor open. Linux permits such numbers; this review's read-only `/proc/self/limits` inspection reported soft/hard `RLIMIT_NOFILE` of 1,048,576. That observation is feasibility evidence, not execution of this scenario or a claim about every future host.
3. Landlock restrictions do not retroactively remove access through already-open file descriptors. Ordinary `read`/`write` are not denied by the seccomp filter. A preconnected socket can also be used by ordinary descriptor I/O without another `socket`/`connect` call.
4. An inheritable descriptor survives `execve`; the fresh Node verifier retains that capability despite the confinement diagnostic. The socket-creation and manifest-write self-probes at `verify-isolated.py:52–62` do not test or remove it.

This establishes a residual-capability path, **not** a demonstrated hostile-package exploit, secret read, network transmission or authority mutation by the current replay code. No such operation was attempted.

**Violated contract:** the implemented custody/verifier handoff must actually remove inherited signer/network/authority capabilities, not merely deny future opens. Assessment deliverable 4 (`engine/docs/v1.3-supervised-deployment-candidate-assessment.md:216`) and the concrete OPERATOR confinement guarantee are not met by a fixed partial descriptor range. This is not the separately deferred creation of production UIDs or qualification of an external hard supervisor: the supplied verifier already claims and attempts complete descriptor closure.

**Essential missing regression:** in a separately authorized disposable process, inherit a non-CLOEXEC FD at or above 65536 with a synthetic readable/writable capability; cross the actual verifier confinement/exec boundary and require it to be absent before reconstruction. Also exercise a preconnected local socket capability under an isolated namespace, without real network or secrets. Assert closure independently of the existing `socket()` and package-write denial probes, and fail closed if complete closure cannot be established. Validate intended standard-stream custody separately. Do not silently skip the high-FD case on a host that supports it or rely solely on normal `spawnSync` defaults closing descriptors. The current custody/replay tests (`P/custody.test.mjs:64–71`, `P/replay.test.mjs:25–34`) use ordinary spawned-child descriptors and do not cover this boundary.

**Disposition:** no repair or regression execution is authorized by this review. Source-review verdict remains BLOCKED on B1.

## 6. Independent verifier: what is and is not established

Beyond B1, the source implements real OS mechanisms, not just an empty environment: x86-64 and Landlock ABI >=3 checks; no_new_privs; a handled filesystem rights mask with only enumerated read grants and restricted execute grants; package directory read-only enumeration; seccomp architecture/x32 guards and socket, ptrace, process-memory and io_uring denial. The syscall policy is a denylist, not a complete process/resource sandbox: it does not prohibit all process creation or ordinary descriptor I/O. Descendants inherit installed Landlock/seccomp restrictions; this is not a promise that no subprocess can ever exist. Standard-stream custody, bootstrap environment, privileges, immutable installation and external resource/deadline control remain host obligations. Same-UID fixture success does not establish those obligations. The network/package-write self-probes and retained producer replay are meaningful but incomplete confinement coverage, specifically missing B1.

# Artifact v1.12 Limitations

Artifact v1.12 closes the deterministic package and bounded-acquisition architecture. It is not a hosted reconstruction platform, wallet dashboard, or mainnet mint release.

## Receipt and package scope

- Package publication currently supports verified `closed_position` receipts only.
- Open snapshots and realized-partial candidates are not eligible for package publication.
- JUP and RAY are the two authoritative golden packages.
- The remaining 64 legacy receipts remain archive-only and continue through validated legacy fallback.
- A package is immutable by receipt identity. Changes to member bytes or frozen reconstruction profiles require an explicit version decision.

## Acquisition scope

- Targeted acquisition requires an explicit wallet, token mint, receipt type, segment index, cursor, historical timestamp window, page cap, transaction cap, retry limit, and timeout policy.
- There is no wallet-wide candidate-discovery workflow that chooses package targets automatically.
- Completeness depends on the Helius Enhanced Transactions provider returning valid, monotonic, sufficiently complete historical pages under the approved bounds.
- Provider schema, historical parsing, availability, authentication, rate limits, and transport behavior remain external dependencies.
- Caps, malformed pages, cursor anomalies, uncertain provider outcomes, unsupported target activity, and normalization ambiguity fail closed rather than producing a partial package.

## Hosted and user-facing scope

- There are no hosted reconstruction jobs or hosted acquisition workers.
- There is no user account system, dashboard, submission queue, database, wallet connection flow, or background job control plane.
- A hosted worker is not authorized to write the production package root.
- Package-native public surfaces remain deterministic read/projection paths; they do not create packages from live provider data.

## Publication and chain scope

- V1.12 performs no mainnet mint.
- The existing devnet mint pipeline remains separate and is not part of the package/acquisition regression runner.
- No deployment, upload, minting, signing, DNS, account, or remote publication workflow is added by this release.
- Dry-run orchestration proves package identity in memory but does not persist a package.

## Filesystem operations

- The atomic package store is supported on the documented Linux/GNU local-filesystem contract and requires an explicit pre-existing root.
- Atomic visibility is per receipt, not a multi-receipt transaction.
- A process failure can leave hidden staging evidence or a fail-closed lock.
- Administrative stale-stage and stale-lock review/cleanup remains operational work; the store does not guess that an entry is stale or delete it automatically.

## Evidence scope

- The controlled live RAY reproduction is retained as private sanitized operational evidence outside Git.
- Raw provider responses and unrelated complete wallet history are not retained by the closeout evidence.
- The live probe is not a deterministic regression and must not be added to `run-v112-regression.mjs`.

# v1.6 Demo Flow

## Source of Demo Receipt

Use the tracked receipt-board manifest:
- `engine/samples/historical-receipt-board.manifest.json`

Take the first `entries[].receipt_hash` in that file as the demo receipt.
That hash must also exist in local canonical inventory for the documented checker and manual flow.

## Automated Checker

Run:

```bash
node engine/src/check-v16-receipt-board-demo.mjs
```

The checker:
- requires at least one manifest entry
- requires the first sample hash to exist in local canonical inventory
- starts the local app in-process
- checks status and content type for receipt-board, proof, verifier, card, card preview, and hosted-preview routes
- asserts no fetch/network calls
- asserts no filesystem changes during the checked flow

It does not use:
- browser automation
- screenshots
- export or publish write paths
- upload, mint, signing, or remote deploy behavior

## Operator Walkthrough

1. Open `GET /api/receipt-board`.
Expected:
- JSON board response
- rows represent selected receipt entries
- invalid or missing entries appear in `excluded_entries`
- required anti-overclaim disclosures are present

2. Open `GET /api/receipt-board/preview`.
Expected:
- standalone local HTML receipt-board page
- receipt-entry framing
- no scripts, external CSS, external assets, remote fonts, or images
- no best-trader, top-wallet, winner, performance, portfolio, or track-record claims except explicit negative disclaimers

3. Copy the first ranked row `receipt_hash`.
Expected:
- hash matches an entry in the tracked board manifest
- hash is present in local canonical inventory

4. Open `GET /api/proof/:receiptHash`.
Expected:
- proof detail JSON for the selected receipt
- trust and disclosure fields remain present

5. Open `GET /api/verifier/:receiptHash`.
Expected:
- compact verifier JSON
- no legacy `verification_hash` fallback
- local inventory-backed framing

6. Open `GET /api/proof/:receiptHash/card`.
Expected:
- compact proof-card JSON
- no lifecycle/upload/mint grids

7. Open `GET /api/proof/:receiptHash/card/preview`.
Expected:
- standalone local proof-card HTML
- title, trust label, receipt hash short form, verifier path, and disclosures

8. Open `GET /api/proof/:receiptHash/hosted-preview`.
Expected:
- standalone local hosted-style proof page
- hosted preview semantics only
- no remote hosting, account, profile, portfolio, leaderboard, competition, or privacy guarantees

## Disclosures To Confirm

Confirm:
- `Ranks selected receipts only. Not traders, wallets, portfolios, or skill.`
- `Selected receipt only. Not a portfolio statement.`
- `Raw quote only. No USD normalization.`
- `Publisher-selected sample set unless an explicit coverage scope is supplied.`
- `No live trading, prize eligibility, anti-wash-trading, or full-track-record claim.`

Also confirm:
- default ranking is `trust_then_time`
- `rank_subject` is `receipt`
- `pnl_scope` is `none`
- no PnL ranking exists in v1.6
- no accounts, profiles, wallet signing, remote hosting, or public competition behavior is implied
- `wallet_display` is currently validated and forward-compatible but effectively no-op because board rows do not expose wallet fields
- `count` currently reflects paged rows, not total ranked rows when pagination is used

# Artifact v1.9 Archive Workflow

The receipt archive lets canonical v1.2 receipt inventory records from separate wallet runs coexist locally.

## Import Current Run

1. Run the wallet pipeline with ledger debug.
2. Confirm the expected receipt exists in the current v1.2 debug inventory snapshot.
3. Import the current snapshot:

```bash
node engine/src/inventory/archive-current-run.mjs
```

The importer reads scanner-normalized current inventory records. It does not parse or copy raw wallet transaction files.

## Archive Identity

- `receipt_hash` is the primary identity.
- Bundle version is `receipt_archive_v1`.
- Canonical receipt fields are preserved unchanged.
- Provenance is separate from canonical receipt fields.
- Machine-specific paths and runtime-only timestamps are excluded from archive identity.
- Genuine receipt, event, upload, and mint timestamps remain material.

## Resolution

Use `buildInventorySnapshot({ includeArchive: true })` for archive-aware local resolution. In v1.9, proof detail, verifier, proof card, proof previews, static export, hosted preview, and receipt-board surfaces use targeted archive-backed lookup.

Default inventory routes remain current-snapshot-only.

## Safety

- Equivalent re-imports are deterministic no-ops.
- Conflicts fail closed.
- Archive diagnostics use archive-relative paths such as `receipts/<receipt_hash>.json`.
- No upload, mint, signing, network, or remote database action occurs during archive import or archive-backed proof resolution.

# Artifact v1.9 Limitations

Artifact v1.9 is a local deterministic archive workflow, not a hosted inventory service.

## Scope Limits

- The fixed runtime snapshot is still overwritten by each wallet pipeline run.
- The archive preserves imported receipt inventory records, not raw wallet transaction history.
- Archive-backed resolution is targeted to proof and receipt-board surfaces only.
- Default inventory API and legacy inventory lookup remain current-snapshot based.
- The existing v1.7 demo checker remains current-snapshot based and is intentionally unchanged.

## Conflict Behavior

- Same `receipt_hash` with a different canonical receipt fails closed.
- Materially different archived proof state fails explicitly.
- Corrupt bundles are excluded and reported through archive diagnostics.
- Conflicts are never resolved by silently preferring current or archived data.

## Product Limits

- Receipt board rows rank selected receipts only, not traders, wallets, portfolios, profiles, track records, or skill.
- Coverage remains receipt-scoped and raw-quote only.
- No USD normalization, PnL ranking, live trading, prize eligibility, or anti-wash-trading claim is added.
- No upload, mint, signing, account expansion, remote database, or deployment behavior is added.

## Operational Note

Server modules used by demo scripts must set `TRADE_ARTIFACT_TEST=1` before dynamically importing `server.mjs`. Importing `server.mjs` first starts the standalone listener and can leave an orphan port-3000 process.

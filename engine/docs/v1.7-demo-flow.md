# v1.7 Demo Flow

## Purpose

The v1.7 demo checker validates local receipt-scoped Coverage Statements across existing JSON and HTML proof surfaces.

It does not fetch live data, upload, mint, sign, deploy, or mutate the board manifest.

## Precondition

Local canonical inventory must contain at least one receipt hash from:

```text
engine/samples/historical-receipt-board.manifest.json
```

If the sample hash is missing, regenerate local sample inventory first.

## Command

```bash
node engine/src/check-v17-coverage-demo.mjs
```

## Checked Routes

The checker starts the app in-process and checks:
- `GET /api/receipt-board`
- `GET /api/receipt-board/preview`
- `GET /api/proof/:hash`
- `GET /api/verifier/:hash`
- `GET /api/proof/:hash/card`
- `GET /api/proof/:hash/card/preview`
- `GET /api/proof/:hash/hosted-preview`
- `GET /api/proof/:hash/export`

## Assertions

The checker verifies:
- proof-detail and verifier coverage equality
- null publication context outside the board
- board-only publisher context
- compact coverage wording on card, board, hosted-preview, and export surfaces
- no board publisher wording outside board preview
- zero fetch calls
- no filesystem changes

## Boundary

Coverage remains receipt-scoped only. It is not wallet, trader, profile, portfolio, track-record, skill, prize, or anti-wash coverage.

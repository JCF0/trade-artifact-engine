# Artifact v1.3 bounded-agent final-proof offline layer

## Status

This layer is an offline-only proof of the authorization, agent-decision, executor-admission, durable consumption/revocation, evidence, and Artifact reconstruction boundaries. It contains no live provider, Solana key, transaction-builder, or submission entrypoint.

A production executor remains mechanically blocked until the mandate freezes all five live-readiness values:

- real human authorization public key;
- real agent-control public key;
- acquisition `not_after` Unix second;
- live RPC budget-table SHA-256;
- final Wiggles executor release SHA-256.

The fixed Ed25519 identities and signer in `final-proof-agent/fixtures/` are test-only. The offline executor core accepts injected fake capabilities and does not implement a Solana signer.

## Authority boundary

Agent provenance is never economic authority. The agent can only authenticate one of:

- `INITIATE_ACQUISITION`;
- `REFUSE_ACQUISITION`;
- `INITIATE_FULL_DISPOSAL`;
- `REFUSE_DISPOSAL`.

The agent cannot supply wallet, route, pool, mint, amount, slippage, transaction profile, tick arrays, blockhash, fee, rebroadcast policy, or disposal quantity. Disposal quantity is exactly `FINALIZED_CHAIN_DERIVED_COMPLETE_ACQUIRED_JUP_BALANCE`.

Human authorization and agent decisions use distinct domain-separated Ed25519 messages. Production modules expose exact-domain canonical-byte constructors and verifiers, but no signing endpoint. Fixed test signing helpers are confined to the offline fixture.

The trusted executor boundary independently binds:

```text
human authorization
→ mandate
→ current readiness challenge
→ unused authenticated agent decision
→ predecessor state
→ executor admission
→ prepared transaction commitment
→ signed transaction intent
```

Episode-ordinal consumption and authorization revocation use one executor-side SQLite authority with `BEGIN IMMEDIATE`, WAL, `synchronous=FULL`, strict tables, unique episode/ordinal/decision/challenge keys, and row-level canonical digests. The database lives in a pre-existing mode-`0700` trusted-executor directory and is mode `0600`. Runtime opening accepts only `state_root`: it cannot initialize an absent database or create an episode. A separate explicit provisioning function creates exactly one initial authorized episode and refuses an existing database. The runtime authority exposes typed decision, signed-intent, revocation, and source-authoritative acquisition-closure transitions; it no longer exposes generic episode-state compare-and-set or episode initialization. Uniqueness is keyed by episode and ordinal, not merely by a decision or challenge ID. Tests prove duplicate and concurrent rejection across separate executor instances, restart persistence, missing-state refusal, monotonic execution checkpoints, and revocation/consumption linearization.

`createWigglesAuthenticatedControlPlaneV1` is the transport-neutral Hermes→Wiggles ingress. Wiggles is configured with the exact live-ready mandate and human authorization; ingress accepts only bounded canonical JSON bytes containing the existing domain-separated Ed25519 agent decision. The decision is revalidated against Wiggles' local mandate, authorization, readiness challenge, predecessor state, executor release, action, ordinal, nonce, and time bounds before the durable reservation. The exposed control plane has no direct key-load or sign method. A separately domain-separated human Ed25519 revocation record is the only revocation ingress.

The durable ordering is:

```text
validate complete authenticated chain
→ atomically reserve episode+ordinal
→ prepare and validate exact bounded transaction commitment
→ durably record PREPARED
→ atomically check revocation and record KEY_LOAD_STARTED_AMBIGUOUS
→ invoke the injected signer boundary
```

A crash before reservation grants no authority. A crash after reservation leaves the ordinal permanently consumed. A crash during preparation remains consumed. A crash at or after `KEY_LOAD_STARTED_AMBIGUOUS` forbids another key load or signing attempt. A human revocation that commits before that key-load checkpoint prevents key loading. If it arrives during the key-load/signing window, the authority durably records revocation without falsely claiming that signing did not occur; any bytes subsequently returned by the in-flight signer must be validated and retained, state advances to `RESOLUTION_REQUIRED_AFTER_REVOCATION`, and release/first submission is blocked. Once `SUBMISSION_POSSIBLE` commits, bytes may have escaped and revocation cannot withdraw them; only identical-byte resolution/finalization is safe. Missing, corrupt, conflicting, inaccessible, blank-replacement, valid-empty replacement, or row-omission state blocks runtime opening or execution.

### Storage trust and rollback limit

The local authority protects against Hermes loss/restart, Wiggles process crash/restart, duplicate delivery, concurrent processes, ordinary file loss, malformed replacement, and internally inconsistent mutation. Hermes memory, conversation state, tmux state, and process-local delivery state are never authority. Provisioning and storage restoration are deployment-administrator operations; the intended live Wiggles runtime identity may open and mutate the provisioned database but must not invoke provisioning. A separately reviewed deployment must enforce those identities and filesystem permissions.

An older, internally valid SQLite snapshot is deliberately **not claimed detectable by this local database**. Checksums, `integrity_check`, and a marker restored with the database cannot establish freshness. The user has explicitly approved option 1 for the Construct proof of concept: one human-authorized, supervised bounded-agent episode, trusted deployment administration, and executor-owned durable state surviving ordinary process crashes/restarts. Automatic detection of administrator restoration is NOT a guarantee of this release. A known restore, reprovisioning, loss of authoritative state, or ambiguous recovery requires stopping the episode, with no automatic reenrollment or execution reset. External generation/head infrastructure is deferred, not implemented; the prior proposal is preserved in `v1.3-bounded-agent-rollback-deployment-decision.md`. The valid-snapshot regression demonstrates this limitation rather than claiming rollback resistance. Other live-release gates remain unchanged; see `v1.3-construct-supervised-release-checklist.md`.

The authenticated control-plane slice does not submit or rebroadcast. The durable authority exposes monotonic successor transitions: preparation fixes the semantic transaction digest before key loading; `recordSignedIntentDurableV1` parses retained legacy Solana wire, checks its hash and message hash, derives its first signature, verifies Ed25519 against the first required signer, and binds these values to the prepared record; submission, inspection, and finalization re-open and re-verify retained bytes. The separate offline-testable Orca message/signing composition now constructs the exact legacy message from frozen mandate definitions and explicit executor-owned build inputs, binds the prepared semantic commitment to those bytes, verifies returned wire, and retains it before the authenticated control plane commits signed intent. This is not an operational production signer or an independent attestation of live quote/pool/fee data. Live readiness capture and deployment confinement remain mandatory gates; the intended production factory stays mechanically blocked. Until signed bytes are durably recorded, `KEY_LOAD_STARTED_AMBIGUOUS` is terminal for automatic execution and cannot generate replacement bytes. The reviewed identical-byte scheduler remains unchanged and is not activated here.

The intended production composition module is an enforced fail-closed surface with no signer dependency or signer argument. Tests show that a supplied signer capability is rejected without invocation. The separately exported offline core remains a test/composition primitive and is not itself an OS security boundary; proving that a future real wallet adapter is reachable only from authenticated Wiggles ingress remains a mandatory executor-release integration gate.

## Evidence and economics

The closed evidence graph binds both legs through transmissions and finalized transaction identities into Artifact reconstruction. Its manifests use canonical JSON SHA-256 member identities and reject hash-inconsistent or cross-episode substitutions. Fully self-rehashed structural provenance remains non-authoritative unless the source-bound gate independently recaptures the corresponding authority.

`validateEpisodeEvidenceGraphStructureV1` is intentionally structural: internal hashes and cross-links establish provenance, not economic authority. Claim promotion is available only through the source-bound finalized-evidence adapter and source-reconstructing final gate validator.

The finalized-evidence adapter recaptures the existing source-bound v1.3 authority and recreates the existing production economic-evidence port. It checks finalized transaction identity, wallet, slot, block time, transaction digest, target continuity, exact acquisition USDC debit, and complete JUP disposal before exposing that port.

Acquisition must close before disposal can be authorized, while the existing production Position bridge intentionally requires exactly two canonical transactions and a zero-target opening and ending boundary. That bridge therefore cannot serve as a pre-disposal acquisition-closure API without circularly requiring the later disposal. No protected bridge or economic semantics were changed. The narrow acquisition-closure adapter instead reuses the existing source-bound authoritative-context validator and full-transaction effect projector over exactly one finalized acquisition transaction. It requires zero opening JUP, ending JUP equal to the independently reconstructed positive transfer, the exact mandated USDC debit, exact transaction identity, and the durable signed-intent/wire identity. Only its in-process branded proof may atomically advance durable state to `ACQUISITION_EVIDENCE_CLOSED`; callers cannot submit evidence digests or quantities to the Wiggles closure endpoint. Disposal challenges are then required by both Wiggles ingress and durable challenge registration to copy the retained acquisition evidence digest and acquired JUP quantity exactly.

Economic values and the final `VERIFIED/CLOSED` claim are produced only by the existing:

- full-transaction projector;
- production Position economic-evidence bridge;
- episode population;
- explicit candidate selection;
- immutable claim issuer.

Mandate, authorization, decision, admission, and transmission records are provenance only.

The offline fixture's `closed_rebroadcast_evidence_sha256` and `terminal_resolution_evidence_sha256` values are deterministic synthetic provenance references, not source-authenticated scheduler archives. They cannot promote or determine economics. A live successor must retain the exact signed wire and complete reviewed-scheduler/terminal evidence and add an independently validated source boundary for those child artifacts; the current offline gate deliberately remains live-blocked and must not be represented as proving those live transmission children.

The offline fixture is a deterministic synthetic authority derived from the frozen controlled mainnet Whirlpool transactions but rebound to the final-proof public wallet/account identities. It does not claim that those synthetic transactions occurred onchain. The machine-readable gate uses the same synthetic-provider qualification and does not emit an onchain-occurrence claim.

## Reviewed reusable components

The exact reviewed identical-byte scheduler and transaction-error validator are vendored byte-for-byte under `final-proof-agent/reused/`. `REVIEWED-SOURCE.json` binds their source archive and file hashes. Tests reject any drift and bind the scheduler's three-send, zero-provider-retry policy.

The existing setup and calibration archives remain immutable predecessors and were not modified.

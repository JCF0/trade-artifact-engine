## 2. Precise cleanup contract and implementation

`engine/deployment/private-binding/verify-isolated.py:15–25` defines `close_inherited_descriptors()`. At line 64 it replaces the old `os.closerange(3, 65536)` call, before `sandbox.restrict()` and before reconstruction/Node exec.

The trusted, single-threaded Python bootstrap calls libc/Linux **`close_range(3, UINT_MAX, 0)`** through `ctypes`, with explicit unsigned argument types and signed return type:

- The upper endpoint is the complete unsigned descriptor domain of the syscall ABI, **not a larger empirical cutoff**. The kernel closes the open descriptors in that domain; there is no user-space million-iteration scan.
- Flags are zero: descriptors are closed immediately, not merely marked close-on-exec.
- No cleanup bound is derived from either current `RLIMIT_NOFILE` value. Descriptors inherited before subsequently lowering both soft and hard limits are included.
- Only intended standard streams 0, 1 and 2 are preserved. OPERATOR now explicitly requires custodian-owned `/dev/null` stdin and exclusively captured stdout/stderr, not authority or network capabilities disguised as standard streams.
- The supported host must provide the libc symbol and working Linux syscall. This host reported glibc 2.39 and the actual syscall succeeded in the behavioral test. Missing symbol/support, a denied syscall or any nonzero result follows the existing sanitized `PRIVATE_VERIFIER_STOPPED` exit path. There is no fallback to partial closure.
- Existing release checks, Landlock/seccomp policy, fixed reconstruction implementation, pinned Node selection, empty environment and disabled worker remain otherwise unchanged. Newly opened permitted runtime descriptors are not confused with inherited capabilities.

# v1.7 Limitations

## Scope

v1.7 Coverage Statements are receipt-scoped metadata derived from existing local inventory, proof, valuation, and verifier fields.

They are not:
- wallet coverage
- trader coverage
- profile or account coverage
- portfolio coverage
- full-track-record coverage
- historical balance proof
- anti-wash-trading analysis
- prize eligibility
- public competition readiness
- proof of skill

## Valuation

Coverage remains raw-quote only. No USD normalization is added.

Raw quote fields are not comparable across tokens or quote assets as performance rankings. v1.7 does not add PnL ranking.

## Event Bounds

Coverage event bounds are descriptive receipt event bounds from existing receipt data. They do not independently prove complete wallet history, position history outside the selected receipt, or historical balances.

Missing event timestamps produce deterministic incomplete coverage. They do not change route success or board eligibility.

## Board Context

The Historical Verified Receipt Board remains publisher-selected unless a future explicit coverage scope is supplied.

Board publisher context appears only on board coverage. Proof-detail, verifier, proof-card, hosted-preview, and static export coverage have `publication_context: null`.

## Eligibility

Board eligibility remains fail-closed:
- canonical receipt only
- `verification_status: verified`
- hash valid
- verifier passed
- schema valid
- consistency valid

Mixed-quote or otherwise unverified receipts remain excluded even if verifier booleans pass.

## Out Of Scope

v1.7 does not add:
- normalization changes
- same-mint multi-input swap aggregation
- new receipt types
- gallery tile coverage display
- accounts or profiles
- hosting deployment
- upload, mint, or signing behavior
- trust-strength promotion from coverage presence

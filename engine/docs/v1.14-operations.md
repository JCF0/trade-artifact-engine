# Artifact v1.14 Operations

## Deterministic operation

From the repository root, run:

```text
node engine/src/run-v114-regression.mjs
```

This command is offline and direct-Node only. It requires no credentials, network, API key, live wallet, package store, or upload/sign/mint capability. It runs no npm wrapper and no controlled live validation. Its child processes receive a minimal deterministic environment with a nonexistent home location.

The runner performs four gates:

1. the safety-adapted v1.13 baseline via `node engine/src/run-v113-regression.mjs`;
2. every `engine/src/wallet-acquisition/*.test.mjs` file through Node's test runner, including retained-provider acceptance and acquisition-to-candidate integration;
3. `node --check` for every wallet-acquisition production module, test, and fixture helper; and
4. the v1.14 runner/documentation consistency self-check.

It fails on a child failure, nonzero exit, malformed or inconsistent TAP, a failed/cancelled/todo test, or any skipped wallet-acquisition/self-check test.

### Sanitized report

A report may include only bounded derived fields such as:

- wallet;
- chain and network;
- lookback profile;
- anchor slot, time, and blockhash;
- pages and signatures examined;
- in-window source count;
- counts for all five dispositions;
- normalized event count;
- finding count;
- acquisition, evidence, and candidate digests;
- candidate and selectable counts;
- terminal reason;
- retry and timeout counts; and
- every completeness gate.

It must exclude raw bodies, URLs, headers, key origin, local paths, environment details, and provider prose.

### Repeated-run comparison

An exact offline replay must remain byte-identical. Two independent live runs may have different finalized anchors, so whole-result digests need not match. Compare their common frozen interval instead. If closed candidate-local evidence is unchanged, receipt-scoped evidence and candidate-local identity should remain stable, preserving the established receipt and package identity.

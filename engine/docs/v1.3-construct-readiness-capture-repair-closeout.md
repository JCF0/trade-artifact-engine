## RC1 — actual per-call and overall deadline acceptance

**Disposition: repaired; focused regression GREEN.**

Source: `orca-readiness-capture-v1.mjs:99–171, 331–344` (paths in this section are under `engine/src/verification-scope-v1-3/final-proof-agent/`).

- Overall timer is armed before capability work begins; the monotonic start is taken before reopening authority, so that work consumes the same overall budget.
- Each RPC records a private absolute monotonic call deadline capped by the remaining overall budget.
- On successful transport resolution, after asynchronous evidence retention, and before returning an accepted result, `inTime()` checks the overall operation and the actual monotonic call deadline. Equality is expired. Timer delivery is not the sole acceptance predicate.
- Terminal work marks the operation expired. Active controllers are aborted, while late settlement cannot resume an already-rejected promise race into readiness or another request.
- Aggregate/per-method budgets, pagination bounds and the existing bounded identical-message fee retry remain intact. An overdue fee error response is rejected as a timeout rather than taking the otherwise permitted context-lag retry.

The old implementation returned readiness, giving **Missing expected rejection**. The old initial-authority overrun likewise returned readiness. These are executed reproductions, not deductions from the original report.

After repair, overdue success produces one request and no retained evidence; delayed abort-ignoring settlement cannot append evidence or issue another request; initial authority overrun produces zero requests; an overdue fee error makes exactly one fee request. ## RC4 — provider-evaluated history context floor

**Disposition: repaired within the existing trusted provider contract; focused regression GREEN.**

Source: `orca-readiness-capture-v1.mjs:181–188, 232–260`; tests `orca-readiness-capture-v1.test.mjs:163–188` and authenticated `RC4_REFUSED`.

Every history page—including empty termination pages—and every repeated-head request now carries:

- `commitment: 'finalized'`;
- the existing page limit;
- `minContextSlot: opening.context.slot`.

The validated opening context is at or above the finalized anchor, so this is a lower source-evaluation floor relative to both. Cursor pagination adds only `before`; it cannot drop the floor. The repeated head uses the same floor. History failures have no retry/downgrade branch.

This uses the actual `getSignaturesForAddress` configuration supported by the installed pinned Solana RPC contract (`engine/orca-readiness-sdk/node_modules/@solana/rpc-api/dist/types/getSignaturesForAddress.d.ts`, `minContextSlot`). It does **not** invent a response `context` field, filter historical block times as a freshness substitute, or use a generated digest as provider authority. A conforming provider's success to this request attests that the minimum evaluation context was reached; inability to reach it produces an RPC refusal, with no floorless fallback.

The stale-provider regression models that exact contract: without a floor the provider returns consistent old pages and an agreeing repeated head; with an unmet floor it returns `-32016`. The old implementation falsely succeeded at each tested observation. The repaired implementation refuses at the first page, empty terminal page or repeated-head observation with no subsequent history call or readiness. The positive case sets the opening one slot above the anchor and asserts all nine page/head requests retain that higher floor, including cursor requests.

### Explicit source-contract limit

`minContextSlot` is a provider-enforced **evaluation floor**, not a history block-time filter or a cryptographic completeness proof. The existing trusted archival/all-or-error history assumption and controlled non-atomic capture assumptions still apply. A transport/provider that silently ignores the field or cannot faithfully enforce it is **not an admitted live capability**; before live wiring, that capability must be established or capture must remain disabled. Local code cannot detect a provider lying about successful evaluation when this RPC supplies no returned evaluation context. No live endpoint conformance was asserted or tested here. This repair neither weakens that trust boundary nor manufactures historical eligibility.

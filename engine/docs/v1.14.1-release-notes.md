# Artifact v1.14.1 Release Notes

Artifact v1.14.1 is a diagnostic-observability-only patch for the controlled-live operator.

## Changed

- The controlled-live operational report discriminator is `artifact_v1.14_controlled_live_validation_v2`.
- A `safe_failure` with `error_code: malformed_provider_response` includes a closed `failure_diagnostic` object containing only `diagnostic_version`, `stage`, `operation`, and `reason` fixed-enum values.
- Provider-boundary unsafe values use `provider_value_unsafe`, covering non-plain, cyclic, accessor-bearing, sparse, proxy, excessive-depth, excessive-budget, and non-finite values.
- Explicit Enhanced transaction-shape rejection and defensive projector-internal rejection are distinct: `enhanced_transaction_shape_invalid` versus `enhanced_projection_internal_rejection`.

## Unchanged

- Acquisition, evidence, candidate, selection, receipt, and package schemas and semantics.
- Supported provider response shapes.
- Retry policy, page/transaction caps, attempt budgets, and request/overall deadlines.
- PASS/SAFE_FAILURE and error-code decisions for existing fixtures.
- Report path restrictions, exclusive creation, canonical serialization, and mode `0600`.
- JUP/RAY receipt, package, and member identities.
- Capability boundary: no package-store production write, publication, upload, signing, minting, or deployment.

Diagnostics never retain or copy provider bodies, signatures, transaction details, URLs, headers, provider prose/errors, stack traces, credentials, environment values, or other secrets. They are operational report metadata only and are excluded from all authoritative objects and hash preimages.

Historical v1 reports remain unchanged and cannot be retrospectively localized. Any controlled-live run remains separately authorized.

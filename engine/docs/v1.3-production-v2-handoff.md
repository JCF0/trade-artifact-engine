## 2. Freshness: admission versus historical replay

Enrollment's integer interval is inclusive: `not_before <= attestation.issued_at <= authorization.issued_at <= not_after`. New admission additionally requires an explicit trusted current integer time `authorization.issued_at <= now <= enrollment.not_after`; the validator never defaults to wall time. The runtime deadline must be no later than enrollment expiry; current acquisition/runtime/challenge deadlines remain separate and can be narrower. V3 control retains the additional integer `runtime_deadline_unix_seconds`; replay checks its original bound. A future issued attestation is not fresh; an expired enrollment cannot authorize fresh effects. Revocation never grants new scope.

Historical replay verifies the original signatures, all bindings and those signed time relationships without consulting the current clock. Retained readiness/decision dispatch times must lie within the original enrollment interval and not precede authorization issuance. Time passing after a valid episode does not invalidate its retained custody proof. Export uses historical verification, not a renewed grant; it does not reopen, extend or reprovision the runtime. Original eligibility is replayed from retained original chain/capture evidence, never replaced by current wall time or the qualification observation.

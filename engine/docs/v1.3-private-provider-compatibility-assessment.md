# Private deployment: Helius provider-authentication compatibility assessment

Date: **2026-09-10 (UTC)**. Scope: static source/identity inspection, unauthenticated public official documentation, and this document only. No implementation, activation or new acceptance execution is authorized by this assessment.

## 1. Compatibility verdict and next action

**The accepted binding cannot express the explicitly documented Helius mainnet Solana JSON-RPC authentication contract unchanged.** Helius documents an `api-key` query parameter at the standard mainnet RPC endpoint. The binding requires an Authorization bearer header and rejects every query string. This is a demonstrated configuration mismatch, **not proof that Helius rejects every possible bearer alternative**. No affirmative bearer contract for this service was found in the inspected official documentation.

**Recommend one small, disabled successor slice: a fixed Helius-mainnet query-key capability in the existing private exchange and credential loader, with offline privacy/transport/composition regressions.** Preserve the bearer exchange contract for historical callers/fixtures; do not reinterpret its `bearer` field as a query key. Pin the new production capability to the standard mainnet HTTPS endpoint and one authentication placement in reviewed source. Do not add a general URL/authentication selector, provider comparison, SDK replacement, proxy, Sender route or activation flag.

The standard RPC method family is documented as supported, but deployment compatibility remains **conditional**, particularly for exact unsigned simulation parameters, complete finalized history/owner enumeration, context floors, finite latency/body budgets, credential-echo behavior and account entitlements. Documentation and synthetic acceptance are not real-provider or host qualification.

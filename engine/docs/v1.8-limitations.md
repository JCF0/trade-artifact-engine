# v1.8 Limitations

## Scope

v1.8 is a normalization closeout for one safe swap shape: multiple wallet-side inputs of the same token mint and decimals into exactly one wallet-side output transfer.

It is not a general multi-hop or portfolio expansion.

## Unsupported Shapes

v1.8 fails closed for:
- mixed input mints
- mixed input decimals
- multiple output transfers, even when output mints match
- multiple output mints
- simultaneous native and token input
- same input and output mint
- ambiguous ownership or direction
- unexplained extra wallet-side sent or received assets
- LP, staking, transfer-cost-basis, bridge, or lending flows
- mixed-quote valuation
- USD normalization

## Receipt Effects

When local inventory is regenerated, v1.8 can produce new receipts from events that previous normalization dropped. Existing stored receipts are not rewritten.

Canonical receipts, candidate hashes, verifier inputs, and board eligibility remain unchanged for already stored receipts.

## Diagnostic Metadata

The aggregation helper preserves raw input references only in diagnostic metadata during normalization. Those references must not enter canonical-facing event fields, ledger entries, candidate records, receipts, verifier inputs, or hashes.

## Board and Inventory

The Historical Verified Receipt Board remains receipt-scoped and verified-only. v1.8 does not change board selection, ranking, coverage, or manifest semantics.

Current runtime inventory paths are fixed output paths. They cannot safely retain receipts from several wallet runs at the same time through the normal pipeline output workflow. Do not edit the board manifest to add the new RAY receipt unless a future deterministic multi-receipt inventory workflow exists.

## Mutable-Cache Test Debt

Two legacy pipeline tests depend on mutable local raw cache data and are intentionally excluded from the deterministic v1.8 runner:
- `engine/src/pipeline/regression-test.mjs`
- `engine/src/pipeline/test-receipt-v11.mjs`

These tests already fail against committed HEAD when run with the current local cache because they expect an old receipt count. v1.8 does not fix this test debt.

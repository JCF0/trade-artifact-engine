# Private supervised integration (live entry points remain disabled)

This implementation is an offline-qualifiable private composition, not live activation or proof of provider/host custody. Acceptance results belong in the separately retained completion/checkpoint record; this document alone does not certify GREEN.

## Construction and authority

`createPrivateSupervisedWigglesRuntimeV1` in `final-proof-agent/wiggles-trusted-runtime-v1.mjs` applies the strict production configuration validator and closed phase-budget profile before opening existing authority. The separate disposable-wallet constructor exercises the same composition without admitting the final wallet. The existing live factory and supervised launcher remain refusing surfaces.

The administrator fixes transport, clocks, submission adapter and supervision journal at construction. None is supplied through the agent channel. The only agent decision surface accepts authenticated canonical decision bytes; trusted operations address durable ordinals rather than caller-selected wire, quantities or source paths. Revocation remains a separate authenticated supervisor surface.

Provisioning is explicit and separate: `provisionCrashDurableDecisionAuthorityV1` provisions authority and `provisionSupervisedJournalV1` provisions the evidence journal in the private root. Runtime/journal opening never creates missing authority or a missing journal head. Do not apply provisioning to an existing episode or repair a damaged head in place.

## Captures, simulation and transmission

The approved budget digest binds distinct capture, simulation, submission and economic-source budgets. Phase consumption is durable before effects; its marker is cross-checked against the hash-linked journal and durable head. Journal append fsyncs file bytes, publishes the head and fsyncs the directory. Interrupted or missing state fails closed; there is no automatic restart/reset policy. This detects the tested losses/corruption, not administrator restoration of an internally valid complete snapshot. External rollback infrastructure remains deferred under trusted administration.

The bounded RPC wrapper retains exact request/response bytes, checks per-call and overall deadlines, limits methods/calls/body size, aborts timed-out requests and refuses late evidence publication. It does not authorize hidden retries or credential-bearing diagnostics. The transport implementation itself must be qualified at deployment for endpoint ownership, no redirects/retries, network identity and credential handling.

Exact-message unsigned simulation runs before key access. Simulation identity includes the request, response, message hash, context and timings; offline replay reconstructs the simulation request from the captured fixed message. Existing post-key-I/O freshness and revocation checks remain. Submission uses the explicit supervised profile, existing durable owner election and bounded identical-wire scheduler: no rebuilding, refreshing, replacement signing or provider retries.

## Whole source and terminal projection

Finalized source acquisition retains the original three history lanes, exhaustion pages, repeated heads, finalized context floors, owner enumeration and required transaction bodies. It validates overlapping rows rather than double-counting them. Setup transaction bodies outside the economic lookback are retained and structurally/signature/slot/time/error-bound to that history; they are not inserted into episode economics and do not replace authenticated setup archive obligations. Unsupported or missing bodies fail closed under the bounded source profile.

The fixed lookback and whole episode opening remain unchanged. `projectTrustedTerminalLegV1` selects the exact signed ordinal from the full source, validates durable acquisition basis and quantity for disposal, and checks the original intermediate owner enumeration against the acquisition/disposal boundaries. Unexpected intervening activity is not silently filtered into an apparently complete leg.

`captureRetainedOutcomeSourceV1(ordinal)` obtains bounded read-only evidence for incomplete outcomes after an original capture. It shares the economic-source phase budget and cannot sign, submit or close authority. A retained source is reused rather than replenishing that budget.

## Operational export and independent reconstruction

`inspectRetainedExportCandidatesV1(ordinal)` exposes the source-derived candidate population. `exportRetainedEpisodeV1({ ordinal, selection })` accepts either no selection or the exact population/member digest pair. It writes a fresh fixed child destination beneath private episode state; there is no caller-selected output path or overwrite mode.

The exporter emits actual retained capture records, authenticated decisions/revocation, exact signed wire, original submission files and full source members with a flat JSON manifest. It does not construct final economics or copy a hand-built verifier fixture. A failed export remains evidence; it is not deleted or overwritten.

`reconstructFinalEpisodeReleaseV1` reads only the manifest-bound package. Supervised replay validates phase budgets, journal linkage, original RPC bytes/deadlines/query parameters, setup bodies, simulation/message binding, exact signed control and transmission, full history and source-derived terminal projection. Finalized fees must equal the captured authenticated exact-message fee, including failed execution. Authentication, original eligibility, transmission completeness and economic outcome remain separate result dimensions: missing eligibility does not erase an authentic signature, but it cannot yield a satisfied demonstration contract.

The maintained exporter tests invoke reconstruction in a fresh Node process with an empty environment and `/tmp` working directory. Complete output, acquisition-only, refusal, revocation, finalized failure and unresolved outcomes are exercised from the composed producer. Rehashed deadline, fee, controller, ordinal, signature, capture-reference and submission-binding contradictions must not become successful demonstrations. Synthetic success remains explicitly distinct from live success.

## Deployment gates, not supplied by these tests

- Independent review/approval of the final source and installed dependency/runtime/configuration release bytes.
- Authentic human/controller ownership, setup archive/freeze evidence, approved production budgets and execution interval.
- Actual supervisor/controller/runtime UID and FD isolation; immutable release roots; inaccessible real keys/state; clean environment; no debugger/core dumps or automatic restart.
- Real filesystem/WAL/fsync qualification and stop-on-loss/restoration procedures.
- Provider/transport conformance, bounded bodies/deadlines, zero hidden retries, supported transaction formats, finalized contexts and complete history/enumeration.
- Separately authorized fresh live read-only eligibility/source capture, followed by separate signing/broadcast approval.
- A reviewed activation change. Neither live entry point is enabled by these adapters, documentation or configuration values.

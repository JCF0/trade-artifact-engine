# Artifact v1.14 Wallet-Wide Bounded Acquisition v1

## Boundary and authority

v1.14 is a read-only acquisition boundary for one wallet and one permitted fixed latest-state lookback. It produces a provider-neutral `wallet_wide_acquisition_result_v1`; candidate evidence and package construction remain pure downstream operations.

### Canonical history authority

Finalized Solana `getSignaturesForAddress` history is the completeness index. Enhanced Transactions provide enrichment only, for the exact requested canonical signature set. Enhanced address history alone is insufficient to establish complete wallet history.

A coherent upper boundary binds mainnet-beta genesis, finalized anchor slot, anchor block time, and anchor blockhash. Pagination starts at a null cursor. A latest-state head recheck detects signatures that newly appear at or below the anchor; such a stale first view fails closed. Completion requires either an older lower-bound sentinel or genuine provider exhaustion. Caps, truncation, timeout, uncertainty, stale indexing, malformed pagination, enrichment mismatch, or protocol contradiction produce no acquisition result.

Exact signature-set reconciliation rejects missing, extra, duplicated, or contradictory enrichment within the observed provider boundary.

### Provider trust

This is a provider-attested completeness model. It is not a trustless cryptographic proof against a malicious or jointly inconsistent Solana RPC/indexer pair. Finality, exact set reconciliation, head recheck, and pagination proofs detect ordinary omission, duplication, stale views, and contradiction within the observed provider boundary; they cannot prove that colluding providers reported all chain facts.

## Fixed lookbacks

The pure request contract recognizes exactly:

- `lookback_7d_v1` — 604,800 seconds;
- `lookback_30d_v1` — 2,592,000 seconds;
- `lookback_90d_v1` — 7,776,000 seconds; and
- `lookback_180d_v1` — 15,552,000 seconds.

It permits no arbitrary historical end date. The lower bound is derived exactly:

```text
oldest_allowed_timestamp
= anchor_block_time - requested_lookback_seconds
```

The request validator binds each profile to its exact duration. Future hosted policy may initially enable only 7d and 30d even though the pure contract understands all four profiles.

## Exhaustive transaction dispositions

Every authoritative in-window source receives exactly one disposition:

1. `supported_normalized_event`;
2. `unsupported_activity`;
3. `ambiguous_activity`;
4. `unrelated_activity`; or
5. `failed_transaction`.

The authoritative source-signature set and disposition-signature set must be exactly equal. A supported disposition references exactly one event; v1 allows at most one supported event per source transaction. Multiple swaps, swap-plus-transfer with distinct economics, batch operations, several economic outputs, or another material operation are unsupported or ambiguous rather than partially accepted.

Token-local unsupported or ambiguous activity blocks only affected position tokens. Quote context is retained separately and does not block unrelated candidates. If wallet impact cannot be localized safely, acquisition stops before evidence-bundle issuance. Unrelated and failed sources remain disposition-accounted but produce no normalized event.

## Whole-transaction normalizer boundary

Support is granted only after inspecting the complete transaction and inventorying wallet-affecting operations. Structured swap evidence has priority. Fallback evidence requires a recognized Jupiter, Raydium, or Orca program and exact two-sided wallet economics.

Account closure alone is not trade evidence. Provider types `UNKNOWN` and `CLOSE_ACCOUNT` may normalize only when exact recognized-program and two-sided economic evidence establishes one supported spot operation. Otherwise they fail closed to an unsupported or ambiguous outcome.

The retained RAY buy preserves and aggregates its two wallet-owned USDT inputs exactly: 24,975 USDT plus 25 USDT equals 25,000 USDT. Raw-amount inference fails closed when a numeric provider value cannot uniquely identify one integer raw amount; binary-float multiplication is not treated as authoritative recovery.

The normalizer requires conservative wallet ownership and fee-payer alignment for supported events. Delegated or sponsored swaps do not become supported normalized events under v1.

For a successful wallet-paid transaction, a valid nonnegative fee and an explicit analyzed-wallet native-balance row must reconcile exactly with native transfers, structured native swap legs, and instruction-bound closure rent. Missing evidence is not numeric zero. Wallet-directed closure rent is reconciled separately and never becomes sale proceeds; an external closure-rent destination is material and becomes token-local unsupported/ambiguous activity when the closure mint is known, or wallet-wide unresolved impact when it is not.

## Determinism and downstream identity

Canonical source/disposition equality, canonical event order, and dense wallet-wide `raw_index` assignment make output independent of Enhanced response permutation. The exported acquisition-result constructor and validator independently require canonical event order and exact indexes `0..N-1`; callers cannot bypass this authority by avoiding the acquisition orchestrator. Permitted canonical page layouts, including synthetic post-anchor fillers, also preserve authoritative acquisition bytes.

The integrated deterministic proof builds acquisition, `candidate_evidence_bundle_v1`, `wallet_candidate_set_v1`, digest-only resolution, the exact existing Slice 7 `dry_run` request, and a targeted in-memory package dry run. No package-store capability is supplied. The unchanged package boundary remains `receipt_package_v1`.

Unrelated later wallet evidence can change set-wide evidence and candidate-set digests. It does not change unaffected receipt-scoped evidence, candidate-local identity, or the resulting closed receipt/package identity.

All acquisition-result exports now share complete authoritative disposition accounting and native Solana identity validation. Provider ports must carry the hidden acquisition-wide starter; no semantic method is awaited before it binds immutable budgets. Production deadline arithmetic uses a single monotonic origin. Retry telemetry counts begun retry attempts; timeout telemetry counts actual effective transport-timeout terminations once.

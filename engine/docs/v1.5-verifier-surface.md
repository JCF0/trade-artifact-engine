# Artifact v1.5 Verifier Surface

## Scope

Slice 2 adds a compact, read-only verifier API for inventory-backed v1.2 receipts.

Route:
- `GET /api/verifier/:receiptHash`

This surface:
- reads local inventory/proof-detail-derived verifier facts only
- uses Slice 1 trust and disclosure helpers
- validates `receiptHash` against `^[a-f0-9]{64}$`
- does not rerun the ledger verifier
- does not perform network verification
- does not write files, create directories, upload, mint, sign, or fetch remote data
- does not fall back to legacy `verification_hash`

## Response Shape

Successful responses return HTTP `200` and the compact object below:

```json
{
  "receipt_hash": "<64-char lowercase hex>",
  "receipt_id": "art_v12_cp_TEST_0",
  "receipt_type": "closed_position",
  "valuation_status": "raw_quote",
  "verification": {
    "recomputed_hash": "<64-char lowercase hex|null>",
    "hash_valid": true,
    "verifier_passed": true,
    "verifier_schema_valid": true,
    "verifier_consistency_valid": true,
    "verifier_rule_violations": []
  },
  "trust": {
    "current_level": 4,
    "current_code": "source_anchored",
    "current_label": "Source Anchored"
  },
  "disclosures": [
    "Selected receipt only. Not a portfolio statement.",
    "Raw quote only. No USD normalization.",
    "Wallet display may be truncated or redacted by publisher.",
    "Hosted, unlisted, and private labels describe display or distribution choices only. They do not increase proof strength."
  ],
  "instructions": {
    "mode": "local_inventory_backed",
    "summary": "Local inventory-backed verifier view only. This surface does not rerun the ledger verifier and does not perform network verification.",
    "proof_api_path": "/api/proof/<receipt_hash>",
    "inventory_api_path": "/inventory/<receipt_hash>",
    "local_command_template": "node engine/src/verify/verify-receipt.mjs <receipt.json>"
  }
}
```

If source anchors are exposed, the disclosures array also includes the correlatability disclosure from Slice 1.

## Status Rules

- `200` for a known canonical v1.2 `receipt_hash`
- `404` for an unknown but well-formed `receipt_hash`
- `400` for a malformed `receipt_hash`

## Compatibility Notes

- The route is additive and does not modify existing `/api/proof/:receiptHash` behavior.
- Verifier fields remain separate from lifecycle, upload, mint, and display-status fields.
- Existing v1.2 verifier, schema, hash, accounting, valuation, and pipeline logic remain unchanged.

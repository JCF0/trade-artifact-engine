# Artifact v1.6 Historical Verified Receipt Board

## Scope

v1.6 Slice 1 defines the rules and manifest contract for a local Historical Verified Receipt Board.

This slice is documentation and sample manifest only. It does not add API routes, view models, HTML rendering, ranking logic, upload behavior, minting, signing, network calls, accounts, profiles, remote hosting, or USD normalization.

The board is a receipt board, not a trader leaderboard. It orders selected historical receipt entries. It does not rank traders, wallets, profiles, portfolios, skill, prize eligibility, or full track records.

## Safe Naming and Framing

Preferred name:
- Historical Verified Receipt Board

Acceptable short names:
- Receipt Board
- Verified Receipt Board
- Historical Receipt Board

Avoid:
- Best trader
- Trader leaderboard
- Wallet leaderboard
- Portfolio leaderboard
- Skill ranking
- Prize board

Required framing:
- Ranks selected receipts only. Not traders, wallets, portfolios, or skill.
- Historical/local/sample only.
- Not live trading.
- Not a prize competition.
- Not public hosted infrastructure.
- Not an anti-wash-trading system.
- Not a full-track-record or portfolio statement.

## Ranking Contract

Slice 1 only defines the ranking contract. It does not implement ranking.

The default v1.6 metric contract is:

```json
{
  "metric": "trust_then_time",
  "direction": "desc",
  "rank_subject": "receipt",
  "pnl_scope": "none"
}
```

Rules:
- `rank_subject` must be `receipt`.
- Rows represent selected receipt entries.
- The manifest may declare ordering intent, but runtime ranking is deferred.
- Trust level may be displayed or used by future board logic only as receipt proof context, not as performance quality.
- Time-based ordering may be used only from existing receipt/inventory timestamps.
- PnL ranking is not implemented in Slice 1.
- `raw_quote_pnl_pct` is deferred unless a later slice confirms canonical fields and safe display rules.

Do not rank:
- Traders.
- Wallets.
- Participant identities.
- Accounts or profiles.
- Full portfolios.
- Win rate.
- Volume.
- Drawdown.
- Risk-adjusted return.
- USD-normalized returns.
- Cross-token raw quote returns as comparable performance.
- Any anti-wash, sybil, or prize eligibility metric.

## Manifest Path

Tracked manifest path:

```text
engine/samples/historical-receipt-board.manifest.json
```

The manifest lives under `engine/samples/` because `engine/data/` is generated runtime state and is gitignored.

## Manifest Schema

```json
{
  "version": "1.0.0",
  "board_id": "historical_verified_receipt_board_demo",
  "title": "Historical Verified Receipt Board",
  "subtitle": "Selected historical receipts only. Not a trader leaderboard.",
  "selection_scope": {
    "mode": "publisher_selected",
    "statement": "Publisher-selected sample receipts for local prototype demonstration."
  },
  "ranking": {
    "metric": "trust_then_time",
    "direction": "desc",
    "rank_subject": "receipt",
    "pnl_scope": "none"
  },
  "entries": [
    {
      "receipt_hash": "<64-char lowercase hex receipt hash>",
      "display_name": "Entry 1",
      "participant_ref": "local-entry-1",
      "selection_note": "Demo receipt selected by publisher."
    }
  ]
}
```

Field rules:
- `version` identifies the manifest contract version.
- `board_id` is a local board identifier, not a remote platform identifier.
- `title` and `subtitle` must avoid trader, profile, portfolio, skill, and prize claims.
- `selection_scope.mode` is `publisher_selected` for Slice 1.
- `selection_scope.statement` must explain the sample set in plain language.
- `ranking.metric` declares future ordering intent.
- `ranking.direction` declares future ordering direction.
- `ranking.rank_subject` must be `receipt`.
- `ranking.pnl_scope` is `none` for Slice 1.
- `entries[].receipt_hash` references a canonical v1.2 receipt hash.
- `entries[].display_name` is a row label only.
- `entries[].participant_ref` is an opaque local row/grouping reference only. It is not an account, profile, identity, wallet ownership claim, or login handle.
- `entries[].selection_note` explains publisher selection and must not claim skill or full performance.

## Fail-Closed Rules

Future board implementations must exclude a row from ranked output when:
- `receipt_hash` is missing or malformed.
- The receipt is not found in canonical v1.2 inventory.
- The row only matches a legacy `verification_hash`.
- The receipt hash is invalid.
- The verifier did not pass.
- Schema verification did not pass.
- Consistency verification did not pass.
- The canonical receipt `verification_status` is not board-eligible; v1.6.1 permits only `verified` rows and reports `verification_status_not_board_eligible`.
- The receipt type is unsupported for the declared metric.
- Required canonical fields for the declared metric are missing.
- The metric would require USD normalization.
- The metric would require live data, network calls, wallet signing, upload, minting, account state, or profile state.

Slice 1 does not implement these checks. It defines the required behavior for future slices.

## Excluded vs Lower Confidence

Excluded rows are rows that must not appear in ranked output. Examples:
- Missing receipts.
- Malformed hashes.
- Invalid hashes.
- Unverified receipts.
- Unsupported receipt types for the selected metric.
- Rows requiring unavailable or non-canonical metrics.

Lower-confidence display is deferred for future implementation and must be explicit. Examples that may be displayed with lower confidence in a non-ranked section later:
- Receipts without source anchors.
- Receipts without an explicit coverage statement.
- Publisher-selected rows where no coverage scope is supplied.
- Open snapshots that are not eligible for PnL ranking.
- Raw-quote-only receipts where no USD normalization exists.

If future implementation cannot clearly distinguish ranked rows from lower-confidence or informational rows, it should fail closed and omit those rows from ranking.

## Required Disclosures

Every future board API or preview surface must include:
- Ranks selected receipts only. Not traders, wallets, portfolios, or skill.
- Selected receipt only. Not a portfolio statement.
- Raw quote only. No USD normalization.
- Publisher-selected sample set unless an explicit coverage scope is supplied.
- No live trading, prize eligibility, anti-wash-trading, or full-track-record claim.

## Deferred Coverage Statements

Coverage-scoped behavior is not available in Slice 1.

Future slices may add coverage-scoped behavior only if an explicit coverage statement is supplied and surfaced. A coverage statement must describe:
- What receipt population was eligible for inclusion.
- What time range, wallet scope, token scope, or source scope was used.
- What was excluded.
- Whether the board remains publisher-selected.
- Why the scope does not imply full portfolio or trader performance.

Coverage statements must not be inferred automatically from a manifest title, participant reference, wallet, or receipt set.

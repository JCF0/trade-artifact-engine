## Implemented capture rules

- Transport, clock, explicit deadlines/budget, evidence sink and reopened episode authority are executor configuration, not decision fields. The same capture object is supplied as `readiness_challenge_port` and `build_input_port` to the existing offline Orca composition.
- Every actual RPC attempt, including calls nested inside the existing controlled owner-enumeration adapter, uses the same method/total counters and timeout wrapper. Raw response strings and request bodies are retained through the trusted evidence sink before parsing. Headers, endpoint URLs and credentials are not transport inputs to this module or retained request metadata.
- Genesis must match the mandate. A finalized slot and non-null finalized block establish the chain-time anchor. Anchor block time must not be in the future or older than the explicit freshness interval.
- Finalized wallet/JUP ATA/USDC ATA reads enforce the mandate's opening quantities and classic account identities/authority/state. Both complete owner lanes must pass the existing controlled source-authority machinery; exactly two classic accounts and no Token-2022 accounts must agree with the opening read at an equal reported watermark.
- History uses the existing signature-page validator. Each of wallet/JUP ATA/USDC ATA is paginated to an explicit empty page, with duplicate/order/anchor checks and a repeated head comparison. Missing history, an unexhausted page budget, unexpected post-setup signatures or a changed head refuses capture. The observed latest pre-acquisition history time must corroborate the frozen setup time. Strict eligibility is `anchor_time - 604800 > latest_setup_time`, reusing the lookback-boundary function; candidate wall-clock time is not the proof.
- This is provider-attested history and controlled cross-call consistency, not cryptographic completeness or an atomic standard-RPC snapshot. Capture does not rehydrate a new v1.3 economic claim from these history rows. The production economic pipeline remains untouched.
- Execution-time route, quote, blockhash and fee are separate observations, although this profile requests finalized commitment for all. Initial pool → atomic route → blockhash → fee context floors are enforced. The pool identities, vault mints/owners, tick derivation and decoded tick-to-pool relationships are checked. This profile refuses absent tick arrays rather than synthesizing them empty.
- The strict minimum and exact serialized message are built locally. `getFeeForMessage` receives precisely that message, and the returned fee must equal the mandate. The source retains the exact message hash. Finalized block height must be below last-valid height; no blockhash refresh or requote is performed.
- Disposal loads acquired quantity/evidence identity from reopened episode state and the retained first-ordinal transaction signature. Fresh balances and post-setup history must reconcile with them. Zero-JUP opening is not reapplied; caller-selected or partial quantity is not an input.
- Capture expiry is the minimum of capture-start-plus-freshness, explicit capture deadline and, for acquisition, human acquisition expiry. Cached sources refuse expiry or another challenge. The composition invokes a second freshness check immediately before its signer callback, after the existing durable ambiguity checkpoint.
- A retained capture manifest records source, challenge, raw-evidence digests, validation context, enumeration, counters, budget and acquisition-evidence identity. A hash binds those bytes; it does not independently authenticate a provider or make a synthetic fixture live evidence.

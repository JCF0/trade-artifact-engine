# Artifact v1.6 Limitations

## Slice 1 Status

v1.6 Slice 1 defines the Historical Verified Receipt Board rules and manifest contract only.

It adds:
- Documentation for safe receipt-board framing.
- Documentation for manifest schema and fail-closed behavior.
- A tracked sample manifest at `engine/samples/historical-receipt-board.manifest.json`.

It does not add runtime behavior.

## Product Limitations

The Historical Verified Receipt Board is a local historical sample concept. It is not:
- A trader leaderboard.
- A best-trader ranking.
- A wallet leaderboard.
- A profile, account, or identity system.
- A public hosted platform.
- A live trading surface.
- A prize competition.
- A prize eligibility system.
- An anti-wash-trading system.
- A portfolio or full-track-record report.
- A claim that selected receipts prove trader skill.

Rows represent selected receipt entries only.

## Ranking Limitations

Slice 1 does not implement ranking.

The manifest declares a default future metric contract:
- `metric`: `trust_then_time`
- `direction`: `desc`
- `rank_subject`: `receipt`
- `pnl_scope`: `none`

This means:
- The future ranking subject is a receipt, not a trader.
- PnL ranking is not active.
- Raw quote PnL percentage ranking is deferred.
- USD-normalized ranking is out of scope.
- Cross-token or cross-quote performance comparison is out of scope.

Trust levels describe proof strength context. They do not prove trade quality, skill, or full performance.

## Manifest Limitations

The sample manifest is publisher-selected.

`participant_ref` is an opaque local row/grouping reference only. It is not:
- An account.
- A profile.
- A login.
- A public identity.
- A wallet ownership claim.
- A trader identity.

`display_name` is a display label only.

The manifest does not prove coverage, completeness, or fair selection.

## Coverage Limitations

Coverage-scoped behavior is deferred.

No coverage scope should be claimed unless a future slice explicitly supplies and surfaces a coverage statement. Without that statement, the board remains publisher-selected.

Coverage statements must not imply:
- Full wallet history.
- Full portfolio history.
- Full trader performance.
- Anti-wash validation.
- Prize eligibility.
- Public competition readiness.

## Verification Limitations

Future board rows must rely on existing proof and verifier outputs.

v1.6 Slice 1 does not modify:
- Canonical v1.2 receipt schema.
- Canonical receipt hash derivation.
- Accounting logic.
- Ledger verifier logic.
- v1.3 inventory behavior.
- v1.4 hosted/static preview behavior.
- v1.5 trust, verifier, proof card, or gallery behavior.

The raw quote boundary remains. No USD normalization is introduced.

## Required Disclosures

Future board surfaces must include:
- Ranks selected receipts only. Not traders, wallets, portfolios, or skill.
- Selected receipt only. Not a portfolio statement.
- Raw quote only. No USD normalization.
- Publisher-selected sample set unless an explicit coverage scope is supplied.
- No live trading, prize eligibility, anti-wash-trading, or full-track-record claim.

## Runtime Limitations

Slice 1 adds no:
- HTTP routes.
- API handlers.
- HTML preview pages.
- View models.
- Ranking modules.
- Tests requiring network.
- Upload, mint, signing, or wallet behavior.
- File writes during request handling.

Any future implementation should remain deterministic, local, read-only, and fail-closed by default.
